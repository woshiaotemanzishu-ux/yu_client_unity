# UI 功能快接

目标是尽快让真实 UI 接口可用，不证明最终验收完成。

## 流程

1. 用老端运行页、源码和 Unity 现状，一次性列出控件、状态、点击、协议和缺口。清单够写代码即可，不建大型台账。
2. 批量实现：
   - 缺功能载体时，只补最小按钮、文本、列表、容器和 Bind。
   - 接 View/Controller/Model、正式协议、回包、即时刷新和重开状态。
   - 复用已有组件；不要恢复完整历史界面或追求视觉一致。
3. 累计成一个逻辑批次，做一次定向编译。只修编译或明确的功能错误。
4. 输出完成项、未完成项和 `visual-pending` / `runtime-pending`，然后停止。

## 不做

- 不启动 UIDAudit 台账、GM、专用账号、PlayMode、WebGL、Headless 或截图证据。
- 不修位置、尺寸、图片、字体、模型、特效和动画，除非缺少它会让功能无法点击或无法表达状态。
- 不因传递弹窗或新依赖递归扩展；只实现当前功能所需最小接口，其余登记。
- 不开发公共工具，不做 Creator/转换器重建，不提交代码，除非用户另有要求。

## 止损

- 参考预算：盘点 20 分钟、实现 30 分钟、编译 5 分钟。
- 连续 10 分钟没有产生清单、目标代码或编译结果，立即停止并说明耗时去向。
- 缺账号状态或运行环境不阻断静态功能实现，标为 `runtime-pending` 即可。
