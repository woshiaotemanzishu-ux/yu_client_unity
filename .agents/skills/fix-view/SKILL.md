# UI 视觉精修

只修用户指定页面的可见差异。当前 Prefab 是唯一视觉源，老端同状态运行画面是目标。

## 流程

1. 固定老端和 Unity 的页面、状态、viewport 与截图，列出本轮可见差异。
2. 直接增量修改当前 Prefab 的 RectTransform、Sprite、文字、层级、裁剪、模型或特效宿主。
3. View/Controller 只处理视觉所需的显隐和生命周期，不把布局写进代码。
4. 按一个视觉批次复验指定状态；输出已修项和仍需人工调整的具体节点/属性。

## 边界

- 已有 Prefab 禁止重转、Creator 重建或恢复整套历史界面。
- 发现按钮、协议、数据或即时刷新缺失时记录为 `function-pending`，转 `ui-function-fast-pass`，不在本轮扩展。
- 发现最终验收需求时在精修结束后转 `audit-game-ui-route`；不得自动启动 GM、Web 构建或整页台账。
- 共享组件只在确认根因属于共享层时修改，并先列直接消费者；普通页面差异不扩成全库检查。
- 连续 10 分钟没有产生 Prefab/视觉代码差异或新视觉证据，立即停止当前方向并报告。
