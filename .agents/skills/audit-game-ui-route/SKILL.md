# 游戏界面运行态巡检

## 目标

把一个界面入口展开成可追踪的功能树。先广度枚举当前页的全部可见/条件控件，再选一个子节点深度优先跑到叶子，包括提交后即时状态、关闭重开、性能和目标页版本。父节点不得因为“能打开”或“主界面大体完整”提前收口。

每轮交付老端事实、Unity 差异证据、功能树/叶子状态、确定性修复和真实 Prefab 自动回归。多条路由成批收口时再补部署后 Web 复验。

开始前读取 [references/yu-client-unity-runbook.md](references/yu-client-unity-runbook.md)。新建或重开路线时，同时读取 [references/route-ledger-schema.md](references/route-ledger-schema.md)并先生成台账。路径、账号或发布地址与项目权威文档冲突时，以当前文档和运行事实为准并更新参考文件。

## 1. 预检与隔离

1. 按项目 `AGENTS.md` 读取全局记忆索引、项目记忆、`Docs/README.md` 及当前模块权威文档。
2. 检查 `git status`。用户工作树有未提交改动时，在独立 `codex/*` worktree 中修改；不得暂存、覆盖或代提交用户现场。
3. 优先使用 Browser MCP 操作老 Web 和 Unity WebGL。网页可操作时不得占用用户电脑；只有无 Web/MCP 通道且用户明确同意时才使用 computer-use。
4. 建立证据目录 `output/ui_route_audit/<日期>_<入口>/`，使用稳定文件名保存截图、日志、耗时和台账。
5. 在点击前保存目标资源目录的文件清单与 `git status --untracked-files=all`。运行后新增的 PNG、`.meta`、模型或配置都必须说明来源；若是页面打开时由编辑器兜底导入，则先记为缺陷，不能把这批本机缓存当作完成证据。

## 2. 先建树，再选一条线跑到底

打开页面后先枚举页签、按钮、列表项、开关、输入、弹窗、条件显隐块、返回链和动态生成入口。为每个节点分配稳定 ID，记录父节点、老端预期、Unity 现状、写入风险和证据。

- 先列同层清单，再选一个未完叶子。沿该分支一直跑到最终显示或可验证的业务结果，修复与复验后才换下一条分支。
- 节点状态只用 `not-run / baseline-only / defect / fixing / needs-runtime-verify / blocked / done`。父节点只有在所有应验叶子为 `done` 时才能是 `done`；子节点 `blocked` 时父节点同样不得完成。
- 将点击分为只读、可恢复写入、破坏性操作。可恢复写入要恢复原值；破坏性操作未获授权时只验到确认框并标 `blocked`，不得因为“弹窗能打开”标 `done`。

## 3. 建立老端事实基线

1. 启动老端资源工具和预览服务；确认端口、页面和账号，不假设服务已就绪。
2. 通过 Browser MCP 沿玩家真实路径逐击。保存入口前、目标页、页签、提交后父页、关闭重开、弹窗、确认框和返回后页面。
3. 记录控件清单、文案、页签/层级、点击语义、协议/回包、即时 UI/Model 变化、重开持久性、返回链和状态恢复方式。
4. 核对跳转页的“页面身份”：当前老端的标题、布局、页签、功能数量和主要资源。同名旧页或占位页不是对等目标。
5. 记录点击到首屏可见、可交互就绪的冷/热耗时。无专项阈值时，超过老端 2 倍或 2 秒先标记性能缺陷并定位，不能只记“最终打开了”。
6. 对关键语义再核对老端源码。运行态行为是第一事实，源码用于解释原因，不用注释代替点击证据。
7. 从页面配置、默认页、全部固定页签和列表候选反推资源依赖闭包。不能只准备首屏或本轮刚好点到的图片；配置里没有有效展示模型/皮肤行的历史条目也不得为了凑数进入列表并触发无效加载。

## 4. Unity 同路径复现

1. 使用同一账号、角色和尽量相同的状态。
2. 浏览器中每次动态读取 canvas 矩形、页面滚动和实际分辨率，不复用硬编码屏幕坐标。
3. 用真实鼠标点击可见元素，收集截图、控制台/协议日志和冷/热耗时。直接调用 `OnClick`、私有方法或路由函数不算运行态点击通过。
4. 事务型叶子必须检查发送前、等待中、成功/失败回包、当前父页即时刷新、关闭重开后的权威状态。“协议发了”或“子窗打开了”不算完成。
5. 跳转型叶子必须核对目标页是当前老端版本，而不是同名旧实现；同时测首次和再次打开耗时。
6. 按视觉/版本漂移、点击面/层级、路由、数据、协议、即时刷新、重进一致性、性能、功能缺失和条件差异分类缺陷。
7. 冷开与热开前后重新扫描资源目录。编辑器运行时触发 `TryImportLooseImageFromClient`、`AssetDatabase.ImportAsset` 或产生新资源/`.meta`，即使最终页面显示正常也判为冷开资源缺失；修复目标是运行前已入库且已登记 Addressables，复验时零新增。

## 5. 诊断与增量修复

- 当前可编辑 Prefab 是视觉事实源。已转换或人工接管的页面不得重跑转换器、Creator 或全量覆盖。
- 视觉问题调用项目 `fix-view` Skill，依据 diff 或截图差异增量修改当前 Prefab。
- 功能问题检查绑定、Flow/Router、Controller、Model、协议与老端调用链。涉及协议时同时核对客户端、服务端和项目负约束。
- 状态问题沿“回包 → Model 权威切片 → 事件 → 已打开 View 刷新”逐段核对，再检查重开时是否从 Model 恢复。不得用退出重进掩盖当前界面不刷新。
- 性能问题区分冷启动资源加载、热重开、重复加载和串行等待，用日志/时间戳找最长阶段。
- 版本漂移先核对当前老端运行页、源码/配置和 Unity 目标模块的功能清单。目标页整体过时时，不在旧页上修一个局部按钮就宣称路线完成；按 `convert-module` 或 `fix-view` 边界处理整页。
- 可见按钮的唯一点击语义必须绑在玩家实际命中的 `Graphic` 上，用 `GraphicRaycaster→PointerClick` 验收。
- 不实现没有老端证据、没有产品授权或会扩大范围的功能。

## 6. 分层复验

1. 运行 `git diff --check` 与离线 C# 编译。
2. 对真实 Prefab 跑 CLI 用例；点击链必须经过 `GraphicRaycaster→PointerClick`。
3. 为事务叶子增加即时刷新、失败、重开回归；为跳转叶子增加目标页版本与冷/热耗时回归。
4. 对资源型页面核对依赖闭包文件均已跟踪、`.meta` GUID 有效、Addressables key 可解析，并在干净检出/隔离工作树中证明页面打开前后零新增资源。
5. 只有选中叶子的各阶段都通过，才标 `done` 并继续同层下一条线。不要为每个小修改都重打 WebGL。
6. 代码改动批量累计后构建 WebGL 壳；资源/Prefab 改动按发布手册决定是否构建内容包。
7. 部署后清缓存或加版本参数，重新登录并严格复走选中分支的全部步骤。
8. 截取修复后同状态画面，并恢复所有可恢复的账号设置。

任一层失败都保留日志并回到诊断。报告必须分开标记“CLI 真实 Prefab 点击已通过”和“部署后 Web 已通过”。

## 7. 记录与收口

报告至少包含：

| ID/父节点 | 叶子步骤 | 老端行为 | Unity 修复前/后 | 即时状态 | 重开 | 耗时 | 版本视觉 | 状态/证据 |
|---|---|---|---|---|---|---|---|---|

列出“已修复叶子”“仍缺失叶子”“被阻塞叶子”和“同层下一条线”。不要把未执行最终事务、未检查即时刷新、未核对目标版本或未测耗时的页面写成已完成。同步更新模块权威文档、`Docs/Shenxiao实施进度.md` 和 `Docs/README.md` 索引。完成提交后按项目规则合并到本地 `main`，并验证用户现场未被误改。
