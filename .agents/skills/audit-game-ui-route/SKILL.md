# 游戏界面运行态巡检

## 目标

把一个界面入口当成可闭环的验收路由，而不是只看 Prefab 或代码。每轮至少交付老端真实行为、Unity 差异证据、确定性修复和真实 Prefab 自动回归；多条路由成批收口时再补部署后的同路径 Web 复验。

开始前读取 [references/yu-client-unity-runbook.md](references/yu-client-unity-runbook.md)。路径、账号或发布地址与项目权威文档冲突时，以当前文档和运行事实为准并更新参考文件。

## 1. 预检与隔离

1. 按项目 `AGENTS.md` 读取全局记忆索引、项目记忆、`Docs/README.md` 及当前模块的权威文档。
2. 检查 `git status`。用户工作树有未提交改动时，在独立 `codex/*` worktree 中修改；不得暂存、覆盖或代提交用户现场。
3. 优先使用 Browser MCP 操作老 Web 和 Unity WebGL。网页可操作时不得占用用户电脑；只有无 Web/MCP 通道且用户明确同意时才使用 computer-use。
4. 建立本轮证据目录：`output/ui_route_audit/<日期>_<入口>/`。截图、浏览器日志和对照表使用稳定文件名。

## 2. 选一条可闭环路由

记录：入口名称、父界面、是否固定显示、老端目标页面、Unity 预期目标、可能改变的账号状态。

- 优先选择无需等级/活动条件的固定按钮。
- 一轮先闭环一个入口及其一层子功能。页面内部还有入口时列入下一层清单，不在未验证前宣称整模块完成。
- 将点击分为只读、可恢复写入、破坏性操作。可恢复写入要在验收后恢复原值；破坏性操作只验证到确认框，不执行最终确认。

## 3. 建立老端事实基线

1. 启动老端资源工具和预览服务；确认端口、页面和账号，而不是假设服务已就绪。
2. 通过 Browser MCP 登录并沿玩家真实路径逐击。每次状态变化都截图：入口前、目标页、页签、弹窗、确认框、返回后的页面。
3. 同时记录：可见文案、页签/层级、点击后语义、是否发协议、是否等待回包、返回链、状态恢复方式。
4. 对关键语义再核对老端源码。运行态行为是第一事实，源码用于解释原因，不用注释代替点击证据。

## 4. Unity 同路径复现

1. 打开当前部署的 Unity WebGL，使用同一账号、角色和尽量相同的状态。
2. 每次动态读取 canvas 的 `getBoundingClientRect()`、页面滚动和实际分辨率，再换算设计坐标；不得复用上轮硬编码屏幕坐标。
3. 用真实鼠标点击可见元素，收集截图、控制台日志、网络/协议日志。直接调用 `OnClick`、私有方法或路由函数不算运行态点击通过。
4. 只有老端和 Unity 的同一路径证据齐全后，才把差异登记为缺陷。分类为：视觉、点击面/层级、路由、数据、协议、功能缺失、条件差异。

## 5. 诊断与增量修复

- 当前可编辑 Prefab 是视觉事实源。已经转换或人工接管的页面不得重跑转换器、Creator 或全量覆盖。
- 视觉问题调用项目 `fix-view` Skill，依据 diff 或明确截图差异增量修改当前 Prefab。
- 功能问题检查绑定、Flow/Router、Controller、Model、协议与老端调用链。涉及协议时同时核对客户端、服务端和项目负约束。
- 可见按钮必须把唯一点击语义绑定在玩家实际命中的 `Graphic` 上；用 `GraphicRaycaster→PointerClick` 验收。只在外层容器补透明 Button 不能替代真实点击验证。
- 不顺手实现没有老端证据、没有产品授权或会扩大范围的功能。

## 6. 分层复验

按风险从快到慢执行：

1. `git diff --check` 与离线 C# 编译。
2. 针对真实 Prefab 的 CLI 用例；点击链必须经过 `GraphicRaycaster→PointerClick`。
3. 上述两层通过后可继续下一条路由，不要为每个小修改都重打 WebGL。
4. 代码改动批量累计后构建 WebGL 壳；资源/Prefab 改动按发布手册决定是否构建内容包。
5. 部署后清缓存或加版本参数，重新登录并严格复走第 3 节的点击序列。
6. 截取修复后同状态画面，并恢复所有可恢复的账号设置。

任一层失败都保留日志并回到诊断，不以“编译通过”代替页面验收。报告必须分开标记“CLI 真实 Prefab 点击已通过”和“部署后 Web 已通过”，后者未跑或失败时不得写成已完成运行态验收。

## 7. 记录与收口

报告至少包含以下矩阵：

| 步骤 | 老端行为 | Unity 修复前 | Unity 修复后 | 状态恢复 | 证据 |
|---|---|---|---|---|---|

列出本轮“已修复”“仍缺失”“下一层入口清单”，不要把未点击页面写成已完成。同步更新模块权威文档、`Docs/Shenxiao实施进度.md` 和 `Docs/README.md` 索引。完成提交后按项目规则合并到本地 `main`，并验证用户未提交现场仍在。
