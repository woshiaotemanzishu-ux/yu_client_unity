# 主角场景自身特效：对标、接入与排障

> 状态：生效
>
> 最后核对：2026-07-29
>
> 适用范围：场景主角的升级、任务导航、任务跳跃、采集完成、任务提交成功演出，以及模型常驻/动作特效

## 一、用户可见症状

- 收到升级协议且等级数字已变化，但角色身上没有升级光效。
- 日志已经显示升级/跑动特效进入播放态，但画面极淡、只闪一下，或低 Alpha 的跑动速度线完全看不见。
- 点击任务自动寻路后角色会跑，长距离跑动却缺少老端的“流星/拖尾”效果。
- 任务跳跃只有位移和动作，没有每段起跳的烟尘/跃迁效果。
- 采集完成后缺少角色自身的一次性完成特效。
- 30004 提交成功并进入下一任务，但没有老端位于画面上层的“任务完成”演出。
- 场景角色与 UI 模型共用装配器时，可能反而把只应出现在 UI 模型上的 `Body.always` 常驻特效带进场景。

`ParticleAttachNode[15] = SceneObj` 的关键语义不是“角色模型父节点”，而是“与角色同位置、脱离模型旋转”。

## 三、最终实现

### 3.1 挂载和资源生命周期

- `SceneCharacterStage.MainRoleDetachedEffectHost` 是 `MainRoleTilt` 的同级节点：同落点、单位旋转，不继承角色 yaw 或 2.5D 倾斜。
- 升级、采集完成均通过 `EffectBinder.AttachOne` 创建，禁止业务代码直接 `LoadAsync + Instantiate`。
- `SceneCharacterStage.MainRoleAttachedEffectHost` 是模型容器下的稳定随身宿主：继承主角 yaw 与 `MainRoleTilt` 的 2.5D 倾斜，但用逆缩放抵消场景模型体量缩放，世界缩放恒为 1。
- 任务跑动拖尾挂到 `MainRoleAttachedEffectHost`，不再挂 `ReplaceableRoleModel.ActiveModel/root`。混合模型从 idle/run/skill 切换实例时宿主不变，不需要销毁重挂。
- 新美术动作 prefab 的空 `root` 位于美术原始坐标。`ArtModelStager` 用 `landingOffset/landingScale` 把人物落点归零后，该 `root` 可能落到人物后方；它还会先继承约 0.37～0.39 的落点归一缩放，再乘主角场景缩放 0.85。实测 1111/1213 run 的旧挂点世界缩放只有 0.315/0.333；把老模型单位制作的 `char_acceleratebuff01` 挂进去会同时产生“拖尾脱离人物”和“御风流光缩成小尾巴”。
- `char_acceleratebuff01` 的三角网格不是常亮尾片：老端 1 秒循环动画把 `_MainTex_ST.z` 从 0 线性滚到 3，贴图 `lyz_trail_117` 的亮区与透明区依次扫过网格，形成流光和周期隐现。Unity 的 `LayaParticleUnlit` 实际也读取 `_MainTex_ST`；若旧 `.anim` 只绑定 `_BaseMap_ST`，贴图会定格成持续可见的实心三角。该资源必须保留 `material._MainTex_ST.z` 的 `0→3` 循环曲线。
- 跳跃位置特效通过 `SceneCharacterStage.AddSceneEffectAnchor` 建空锚点，再由 `EffectBinder` 挂特效。锚点每帧按“特效世界像素 - 当前主角像素”更新，因此角色飞走后烟尘留在原地。

### 3.2 触发与取消边界

任务拖尾必须在以下任一边沿清除：到达、卡死/超时、摇杆接管、技能释放、采集开始、任务跳跃、服务端权威坐标修正、战斗演出冻结、场景主角销毁。新老混合模型切换不算取消，稳定随身宿主保持原实例连续播放。

`MoveType.Accelerate` 只在 150ms 延时结束且特效成功进入活动态后上报；结束帧先保留本次移动类型发最终坐标，再清状态。

### 3.3 透明 RT 合成与任务成功层

- `SceneCharacterStage` 先把角色和粒子混合进透明 RenderTexture，RT 中的 RGB 已经是预乘 Alpha 结果；贴回 UGUI 时必须始终使用 `Shenxiao/UI/StageComposite` 的 `Blend One OneMinusSrcAlpha`。
- 该规则与当前模型有没有 `ArtModelRenderProfile` 无关。若旧跑动模型切入时把 `__SceneChars.RawImage.material` 恢复为默认 UI `SrcAlpha`，升级和速度线会被再次乘 Alpha；`char_acceleratebuff01` 的速度线峰值 Alpha 本就约 0.616，因此尤其容易淡到不可见。
- 项目切到 Linear 后，旧 Laya 粒子材质的 `tint=0.5 × shader 2` 中性约定会被 Unity 先把 0.5 转为约 0.214，最终只剩约 43% 强度。`LayaParticleUnlit` 必须只把材质 tint 恢复为 Laya 制作数值；纹理仍按 sRGB 采样，禁止把整个项目退回 Gamma。
- `effect_xemlvup` 的老资源本身仍是约 2 秒粒子序列，“升级”两层分别约 1.1 秒和 0.8 秒。旧转换产物还把 `other_xemshenji01` 的尺寸关键点自动平滑成了负值，运行时尺寸被钳为 0，并丢失源资源的 0.1 秒延迟；转换器的 `GradientDataNumber` 必须按 Laya 语义使用线性分段，不能用 Unity 自动平滑切线。不要用延长资源时长掩盖这个问题。
- 任务完成是另一条 UI 演出链：`TaskController.On30004(code=1)` 播 `ui_renwuwancheng`，挂 `UILayer.Top`，1.5 秒后释放。老端传入 `(0,+4)` 会落在屏幕上部，Unity 共享 UI 通道没有全局纵向翻转，因此仅本条业务边界映射为 `(0,-4)`；连续成功会先释放旧句柄，重登/注销也必须清理。

## 四、范围边界

本轮覆盖老端 `Role/SceneController/Task` 中能落到当前 Unity 主角实体链的直接自身特效。以下两类经过检查，但不能混作本轮主角直连特效：

- `buffparticle_106_1` 是其他玩家 `protect_time` 的离线保护表现。Unity 当前没有其他玩家角色渲染器，主角模型也没有该字段；在主角上伪造会显示错对象，须随其他玩家实体渲染链接入。
- `BuffListVo` 的通用战斗 Buff 是独立战斗 Buff 生命周期系统，涉及 `20001/20003/20007`、到期、去重、预警圈和所有场景战斗实体；不能只见到 `buffparticle_*` 就永久挂到主角。本轮不改变该子系统范围。
- `effect_mon_caiji` 是采集目标身上的循环特效，不是角色自身特效；继续归采集物渲染链。

## 五、快速排查顺序

1. 先确认触发协议/业务边沿是否到达：升级看 13003，采集看发出的 `20008 flag=2`，任务导航看是否走 `MoveToTaskTarget`。
2. 核对资源 prefab 与 Addressables key，不能因为“没有显示”直接重转资源。
3. 检查特效宿主：`attach_type=15` 应在 `MainRoleDetachedEffects`；骨骼动作特效应在 `ActiveModel`；任务跑动拖尾应在 `MainRoleAttachedEffects`；位置特效应在 `SceneEffectAnchor`。
4. 若日志已出现 `detached role effect played` / `task speed effect attached` 但画面仍淡，先检查 `__SceneChars.RawImage` 是否始终为 `Shenxiao/UI/StageComposite`，再检查 `LayaParticleUnlit` 在 Linear 下的 `0.5×2` 中性采样是否回到 RGB 1.0；不要继续重复改触发门禁。若跑动网格变成常亮实心尾片，检查动画是否把 `material._MainTex_ST.z` 在 1 秒内从 0 滚到 3 且 `WrapMode=Loop`，不要用改挂点掩盖贴图定格。
5. 检查异步加载期间是否已取消或切场景；过期任务必须自弃并释放实例。切换活动模型不应重建任务拖尾。
6. 任务完成缺失时先看 30004 `code=1`，再查 `ui_renwuwancheng` 是否在 `UILayer.Top` 形成 `UIEffectStage` 活实例；它与 `TaskFinishView` 是否打开无关。
7. 运行 `Shenxiao.EditorTools.CliVerify.RolePresentationEffects`，要求资源、直立宿主、真实 `EffectBinder` 挂载、Linear 中性色、升级文字 0.1 秒延迟及 0.55 秒可见尺寸、预乘 RT 合成、场景/距离门禁，以及 Top 层任务完成实例全部通过。

## 六、禁止做法

- 禁止用 `_modelTr.parent` 近似 `attach_type=15`。
- 禁止角色业务代码手工 `ResManager.LoadAsync + Object.Instantiate` 特效 prefab。
- 禁止所有自动移动都显示任务拖尾，或把 `AutoFight` 当作任务导航。
- 禁止按普通像素距离判断 7 格；X/Y 必须分别除以 `LogicRatioX/LogicRatioY`。
- 禁止在任务跳跃中误播 `char_jumpfx_02`。
- 禁止按模型有没有 `ArtModelRenderProfile` 切换场景 RT 合成材质；`SceneCharacterStage` 始终使用预乘合成。
- 禁止为修旧粒子发淡而把整个项目切回 Gamma；旧 Laya 数值渐变禁止交给 Unity 自动平滑切线。
- 禁止用 `TaskFinishView` 或下一次 30001 刷新代替 30004 成功后的 `ui_renwuwancheng`。
- 禁止为了“补全”把其他玩家离线保护或通用战斗 Buff 假挂到主角。
- 禁止把按老模型世界单位制作的任务跑动拖尾挂到新动作 prefab 内部 `root`，也禁止直接放大公共特效 prefab 补偿单个新模型；必须使用 `MainRoleAttachedEffectHost` 的稳定单位空间。
- 禁止把任务跑动流光的周期隐现误判为位置问题并添加固定前后偏移；先保证 `.anim` 写入 shader 真正消费的 `_MainTex_ST`，恢复贴图流动后再观察空间表现。

## 七、2026-07-29：任务跑动流光尾端截断

- `char_acceleratebuff01` 的 `eff_cys_sz01` 并不是只靠贴图 Alpha 成形。老 `.lm` 还带有 32 个顶点色，Alpha 从尾端的 `0` 经 `0.133 / 0.467 / 0.733` 渐变到 `1`，负责把矩形交叉网格收成自然流光。
- Unity 旧产物虽然顶点数仍是 32，但 `Mesh.colors.Length == 0`，因此 UV 亮区扫到网格边界时会露出明显直线截断；这会被误判为“整条特效放反”或“新模型挂点错误”。位置、旋转和 `_MainTex_ST.z` 动画均正确时，不得再旋转或平移整条特效来掩盖该问题。
- 当前 `eff_cys_sz01_mesh.asset` 已从老 `.lm` 恢复完整顶点色。验收必须同时检查 `colors == vertexCount`、Alpha 覆盖 `0..1` 且存在中间渐变值；只验证贴图、材质、UV 曲线或肉眼看到“已经出现”都不够。
- `Laya3DImporter.BuildMesh` 已具备 `COLOR` 导入逻辑，但历史生成资产不会自动补齐；排查老特效硬边时，应先核对实际 `.asset` 的顶点色，而不是只看当前转换器代码。
