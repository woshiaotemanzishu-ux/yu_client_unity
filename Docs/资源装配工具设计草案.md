# 资源装配工具设计草案

本文档只定义资源装配工具的目标、数据模型、界面结构和第一阶段验收标准。当前阶段不继续堆 Editor 面板代码，先把工具要编辑的真实对象捋清楚。

## 目标

这个工具不是资源查看器，也不是路径定位器。它的核心目标是让策划或美术在 Unity Editor 中可视化装配和替换一套角色资源：

- 替换一个角色模型时，能明确看到它属于哪个基础动作组。
- 能看到该角色在不同使用场景下需要哪些业务动作。
- 能预览动作，并看到动作上绑定的特效。
- 能替换模型、动作、特效，并校验骨骼、动作、特效是否完整。
- 能把调整结果保存成可运行时读取的装配配置，而不是只改 Editor 临时状态。

## 当前问题

之前那版面板的问题不是窗口不够多，而是主对象错了：

- 它把动作文件当成主对象，导致界面展示一堆 `.anim`，用户不知道哪些动作真实业务会用。
- 它没有区分四个基础模型/动作组，导致“替换模型后应换哪组动作”没有答案。
- 它没有把模型、动作、特效装成一套，所以替换模型只是换了一个 prefab 地址。
- 它没有把动作特效当成可编辑事件，无法表达一个动作有多个特效、挂在哪个骨骼、何时出现、缩放如何调整。

工具的主对象必须从“资源文件”改成“角色装配套装”。

## 已核对事实

### 四个基础动作组

当前角色动作资源只有四个基础目录：

| 动作组 | 含义 | 当前动作文件特点 |
| --- | --- | --- |
| `1100` | 剑士基础组 | base 动作 + `js_*`/`qs_*` 变体 + show 动作 |
| `1200` | 武姬基础组 | base 动作 + `ngs_*`/`njs_*` 变体 + show 动作 |
| `1300` | 枪使基础组 | base 动作 + show 动作 |
| `1400` | 弓手基础组 | base 动作 + show 动作 |

所以用户说“动作应该分为四个组，因为有四个基础模型，其他可以理解为不同贴图/变体”这个判断是对的。工具界面必须先围绕这四个动作组组织，而不是先铺动作文件。

### 创角默认套装样本

`ConfigLogin.CreateRole.Res` 当前四个默认角色：

| key | head_res | role_res | weapon_res | 创角特效 |
| --- | --- | --- | --- | --- |
| `1@1` | `1100` | `1111` | `1100` | `root = cj_1100` |
| `2@2` | `1213` | `1213` | `1200` | `root = cj_1200` |
| `3@1` | `1300` | `1300` | `1300` | `root = cj_1300` |
| `4@2` | `1400` | `1400` | `1400` | `root = cj_1400` |

以剑士为例，`role_res = 1111` 是模型，动作组应归到 `1100`，武器常驻特效来自 `SceneObjectParticle.Weapon[1100].always.bone_skill_r`。

### 业务动作来自 ConfigModelAni

动作不是全局大列表，而是按业务场景取用。例如：

| 场景 | key | 业务动作槽 |
| --- | --- | --- |
| `LoginCreateRoleView` | `default` | `create2`, `create3` |
| `LoginSelectRoleView` | `default` | `idle` |
| `EquipmentView` | `default` | `idle` |
| `Scene` | `default` | `death`, `idle`, `run`, `attack`, `attack2`, `attack3`, `attack4`, `skill1`, `skill2`, `skill3`, `skill4`, `ride`, `ride2`, `collect`, `skill4_2` |

所以工具展示动作时，应先选“使用场景”，再显示该场景需要的动作槽。动作目录中的其他 clip 只能作为候选资源，不应成为主界面的默认展示。

### 老客户端动作特效规则

老客户端 `UIModelClass3D.LoadActionParticle(action_name)` 的行为是：

- 播放动作时触发。
- 先清掉上一个动作的动作特效。
- 查 `SceneObjectParticle.{Body/Weapon/...}[模型id].action[action_name]`。
- 一个动作下可以有多个骨骼，每个骨骼可以有一个或多个特效。
- 每个特效至少有 `name`，可选 `scale`。
- 挂到骨骼后 local position/rotation 归零，local scale 使用配置 scale，默认 1。

这说明旧数据本身不是完整时间轴系统，而是“动作开始时挂特效”。新工具可以扩展时间、偏移、颜色等字段，但第一阶段必须先如实表达旧数据，不能凭空假设旧配置里已经有时间轴。

## 核心概念

### ActionGroup 动作组

动作组表示一套可复用的骨骼/动作资源。当前先固定为：

- `1100`
- `1200`
- `1300`
- `1400`

动作组负责回答：

- 这个模型能用哪组动作？
- 某个业务动作槽映射到哪个 clip？
- 哪些业务动作缺失？

### ModelSet 模型套装

模型套装是替换的最小业务单位，不是单个 prefab。

它至少包含：

- 套装 id，例如 `role_create_1_1`。
- 角色业务 key，例如 `1@1`。
- 模型 prefab，例如 `object/role/model_clothe_1111/model_clothe_1111`。
- 头部/武器/背饰/翅膀等部件资源。
- 所属动作组，例如 `1100`。
- 默认动作上下文，例如创角使用 `LoginCreateRoleView/default`。
- 默认特效集合。

替换模型时，默认替换的是 ModelSet。工具可以提供“只替换模型 prefab”的高级选项，但主流程不应该这么做。

### ActionContext 动作场景

动作场景来自 `ConfigModelAni`。例如：

- `LoginCreateRoleView/default`
- `LoginSelectRoleView/default`
- `EquipmentView/default`
- `Scene/default`
- `Scene/8003`
- `Scene/50001`

每个动作场景包含一批业务动作槽。

### ActionSlot 业务动作槽

业务动作槽是工具展示动作的主行。例如 `create2`、`idle`、`attack2`。

每一行应展示：

- 动作槽名。
- 当前映射 clip。
- clip 是否存在。
- 是否有动作特效。
- 是否能在当前模型骨骼上挂接。
- 预览按钮。
- 替换按钮。

### EffectSet 特效集合

特效集合分四类展示：

| 类型 | 来源 | 示例 |
| --- | --- | --- |
| 创角骨骼特效 | `ConfigLogin.CreateRole.Effect` | `root -> skills_effect/cj_1100` |
| 模型常驻特效 | `SceneObjectParticle.Body[id].always` | 衣服/身体常驻光效 |
| 武器常驻特效 | `SceneObjectParticle.Weapon[weapon_res].always` | `bone_skill_r -> weapon_effect/effect_model_weapon_r_1100_bone_skill_r` |
| 动作特效 | `SceneObjectParticle.Body[id].action[action]` 等 | `attack2` 下多个骨骼/多个特效 |

### ActionEffectEvent 动作特效事件

第一阶段的事件模型要兼容旧配置：

```json
{
  "action": "attack2",
  "bone": "bone_skill_r",
  "effectDir": "skills_effect",
  "effectName": "effect_xxx",
  "target": "model",
  "time": 0,
  "position": [0, 0, 0],
  "rotation": [0, 0, 0],
  "scale": [1, 1, 1],
  "color": null,
  "source": "SceneObjectParticle"
}
```

说明：

- `time = 0` 表示动作开始时触发，对应旧客户端行为。
- `target` 表示挂接宿主，`model` 挂身体模型，`weapon` 挂武器模型；例如 `SceneObjectParticle.Weapon[1100]` 的常驻特效必须挂到武器实例上。
- 旧配置只有 `scale` 时，导入为统一缩放。
- `position/rotation/color` 是工具扩展字段，不要求旧数据天然存在。
- 一个动作可以有多条事件。
- 每条事件必须能在预览时间轴上看到标记。

## 工具界面

主窗口建议拆成三栏，而不是多个互相孤立的页签。

### 左栏：套装与动作组

左栏显示树结构：

```text
角色默认套装
  1100 剑士动作组
    1@1 剑士默认装 role_res=1111
  1200 武姬动作组
    2@2 武姬默认装 role_res=1213
  1300 枪使动作组
    3@1 枪使默认装 role_res=1300
  1400 弓手动作组
    4@2 弓手默认装 role_res=1400

自定义套装
  ...
```

选中套装后，中栏和右栏只围绕这个套装工作。

### 中栏：预览舞台

中栏是实时预览区：

- 显示当前 ModelSet。
- 可选择动作场景，例如 `LoginCreateRoleView/default` 或 `Scene/default`。
- 可选择业务动作槽并播放。
- 有播放、暂停、重播、时间拖动。
- 时间轴上显示动作特效事件点。
- 播放时实际挂接常驻特效和动作特效。

中栏不是单纯显示模型，它必须能回答“当前动作和特效组合看起来对不对”。

### 右栏：装配编辑

右栏分四块：

1. 套装信息
   - 模型、头、武器、动作组。
   - 替换套装。
   - 替换模型 prefab。
   - 骨骼校验结果。

2. 动作槽表
   - 只显示当前动作场景需要的动作。
   - 每行动作可预览、替换、恢复默认。
   - 缺失时明确提示“业务动作缺失”，而不是混在资源列表里。

3. 特效列表
   - 常驻特效。
   - 当前动作的动作特效事件。
   - 每条事件可编辑 bone、effect、time、scale、offset、color。

4. 校验结果
   - 模型 prefab 缺失。
   - 动作 clip 缺失。
   - 特效 prefab 缺失。
   - 骨骼不存在。
   - 动作组不匹配。
   - Addressables 地址缺失。

## 替换流程

### 替换模型套装

主流程：

1. 选中当前 ModelSet，例如 `1@1 剑士默认装`。
2. 点击“替换套装”。
3. 选择候选 ModelSet。
4. 工具先按动作组过滤候选；不同动作组需要明确警告。
5. 应用后同时切换模型、默认动作组、默认特效集合。
6. 自动执行校验并刷新预览。

这才符合“角色模型换掉，对应动作和特效也换掉”的需求。

### 替换单个动作

单动作替换是局部修正：

1. 选中动作场景。
2. 选中业务动作槽。
3. 从当前动作组的 clip 候选中选择替换项。
4. 工具校验 clip 是否存在、是否能被当前 Animator 播放。
5. 替换后预览当前动作和对应动作特效。

### 调整动作特效

动作特效调整流程：

1. 播放某个业务动作。
2. 时间轴显示该动作已有特效事件。
3. 选中事件。
4. 在预览中显示挂接骨骼和特效。
5. 修改时间、骨骼、缩放、偏移、旋转、颜色。
6. 立刻重播验证。
7. 保存到装配配置。

旧配置导入的事件默认 `time = 0`。新增事件才需要手动设置时间。

## 数据保存策略

不直接改转换产物。工具保存一份装配覆盖配置，例如：

```text
Assets/GameRes/resource/config/client/asset_assembly_profiles.json
```

配置按 ModelSet 存储覆盖项：

```json
{
  "profiles": [
    {
      "id": "role_create_1_1",
      "label": "剑士默认装",
      "businessKey": "1@1",
      "actionGroup": "1100",
      "model": "object/role/model_clothe_1111/model_clothe_1111",
      "weapon": "object/role/model_weapon_r_1100/model_weapon_r_1100",
      "defaultActionContext": "LoginCreateRoleView/default",
      "actionOverrides": {
        "create2": "object/role/action/1100/create2-create2",
        "create3": "object/role/action/1100/create3-create3"
      },
      "alwaysEffects": [
        {
          "bone": "root",
          "effectDir": "skills_effect",
          "effectName": "cj_1100",
          "target": "model",
          "source": "ConfigLogin.CreateRole.Effect"
        },
        {
          "bone": "bone_skill_r",
          "effectDir": "weapon_effect",
          "effectName": "effect_model_weapon_r_1100_bone_skill_r",
          "target": "weapon",
          "source": "SceneObjectParticle.Weapon"
        }
      ],
      "actionEffectOverrides": {
        "attack2": [
          {
            "bone": "bone_skill_r",
            "effectDir": "skills_effect",
            "effectName": "effect_xxx",
            "time": 0,
            "scale": [1, 1, 1]
          }
        ]
      }
    }
  ]
}
```

运行时读取顺序：

1. 原始配置：`ConfigLogin`、`ConfigModelAni`、`SceneObjectParticle`。
2. 装配覆盖配置：`asset_assembly_profiles.json`。
3. 覆盖配置只表达用户改过的内容，不复制全部原始配置。

## 第一阶段纵切

第一阶段只做一个真实可用样本，不做全量大工具。

目标样本：

- `1@1 剑士默认装`
- 模型：`role_res = 1111`
- 动作组：`1100`
- 动作场景：`LoginCreateRoleView/default`
- 业务动作：`create2`, `create3`
- 创角特效：`root -> skills_effect/cj_1100`
- 武器常驻特效：`bone_skill_r -> weapon_effect/effect_model_weapon_r_1100_bone_skill_r`

第一阶段界面只需要完整支持：

- 左栏选中 `1@1 剑士默认装`。
- 中栏能预览模型、播放 `create2/create3`。
- 右栏能看到该套装的模型、动作组、两个业务动作、两个常驻特效来源。
- 缺失资源和缺失骨骼能被校验出来。
- 能替换 `create2` 或 `create3` 的 clip，并保存覆盖配置。
- 能编辑 `cj_1100` 的挂点和 scale，并预览。

第一阶段暂不要求：

- 一次支持所有 UI 场景。
- 一次支持所有模型类型。
- 复杂时间轴编辑器。
- 批量替换全部动作。
- 自动生成完整美术工作流。

## 验收标准

第一阶段完成后，只看这几个结果：

- 面板默认不是动作大列表，而是 `动作组 -> 模型套装 -> 业务动作槽`。
- 剑士创角只显示 `create2/create3`，不会把 1100 目录下所有动作铺出来。
- 替换模型时，工具明确显示它属于哪个动作组。
- 预览时可以看到创角特效 `cj_1100` 和武器常驻特效。
- 动作缺失、特效缺失、骨骼缺失会出现在校验区。
- 保存后运行时能读取覆盖配置，而不是只在 Editor 临时生效。

只要这条纵切成立，再扩展到 `1200/1300/1400` 和 `Scene/default` 才有意义。
