# 场景角色离屏渲染：经验与排障

> 状态：生效
>
> 最后核对：2026-08-06
>
> 适用范围：主场景中的主角、其他玩家、NPC、怪物，以及共用 `SceneCharacterStage` 的 3D 角色合成链

## 一、用户可见症状

场景地图和 2D HUD 正常，角色称号、名字、血条也可能正常显示，但主角、NPC、怪物的 3D 模型全部透明。这个组合症状优先指向共用的离屏合成链，而不是每一种角色模型分别加载失败：

- 主角、NPC、怪物模型统一挂在 `__SceneCharStage/Chars` 下；
- `SceneCharCamera` 把这些模型渲染到 `SceneCharStageRT`；
- `__SceneChars` 的全屏 `RawImage` 再把 RT 合成到 `UILayer.Scene`；
- 名字、称号和血条使用独立 Canvas，排序层高于角色 RT，不依赖 RT 中是否真的存在模型像素。

因此，“能看到血条或称号”只能证明场景对象和头顶 UI 链仍在运行，不能证明 3D 模型已经出帧。

## 二、2026-08-06 故障证据与根因

活服 PlaySmoke 已确认：

- 主角加载完成，当前形象 `clothe=1111`；
- 34 个 NPC 和 4 个怪物进入 visible 状态；
- 合成台共有 58 个 Renderer，其中 43 个 active、9 个在相机视锥内；
- 等待 2 秒后，`SceneCharStageRT` 仍为 `alpha=0, lit=0`。

这说明模型实例、Renderer、相机、RT、RawImage 和视锥都存在，但自动相机调度没有把动态 RT 相机送入实际渲染。使用完全相同的真实 Prefab 显式调用 `Camera.Render()` 后，RT 立即得到足量非透明像素，所以模型资源、材质、动画、Addressables 地址、Renderer 1 和渲染管线资产都不是本次根因。

从 2026-08-04 已知正常提交到故障提交逐项核对后，近期合并没有修改 `SceneCharacterStage`、模型地址、角色材质或 Graphics/Quality/URP 资产。本次不是模型文件被错误合并或删除；全新 worktree/Library 的运行环境稳定暴露了原先对 Unity 自动离屏相机调度的隐式依赖。

## 三、最终修复

`SceneCharacterStage` 的专用相机现在保持 `enabled=false`，根节点上的 `SceneCharacterStageDriver` 在 `LateUpdate` 调用一次 `SceneCharacterStage.RenderFrame()`：

1. 主角/NPC/怪物先完成本帧位置、动画和显隐更新；
2. 驱动器确认 `RawImage` 可见且舞台仍有角色；
3. 复核 RT 尺寸与相机 target；
4. 使用重入保护调用一次 `Camera.Render()`；
5. UGUI 在后续 Canvas 阶段合成刚写入的 RT。

相机禁用是有意设计，不是新的异常。它保证渲染只由一个明确入口驱动，避免 Unity 自动渲染与手动渲染在同一相机上叠加。每帧仍只渲染一次，不增加第二份场景角色相机成本。

Unity 官方接口依据：[Camera.Render](https://docs.unity3d.com/cn/6000.0/ScriptReference/Camera.Render.html) 说明手动渲染应使用禁用的专用相机；[Camera.targetTexture](https://docs.unity3d.com/ja/current/ScriptReference/Camera-targetTexture.html) 说明相机输出会写入绑定的 RT。

关键文件：

- `Assets/Scripts/Common/UI3D/SceneCharacterStage.cs`
- `Assets/Scripts/Common/UI3D/SceneCharacterStageDriver.cs`
- `Assets/Editor/CliVerify/Cases/SceneCharacterRenderCase.cs`
- `Assets/Editor/CliVerify/PlaySmoke.cs`

## 五、禁止做法

- 禁止用“Prefab 能加载”“Renderer 数量非零”“Animation 已播放”代替 RT 真实像素证据。
- 禁止因为三类角色同时透明就分别重导主角、NPC、怪物，或盲改 Addressables 地址。
- 禁止在启用自动渲染的同一 Camera 上从 `EditorApplication.update` 重入 `Camera.Render()`；Unity 6 + D3D12 下这会进入不安全的重复渲染路径。
- 禁止把 `camera.enabled=false` 改回 true 来“修复”诊断日志；手动驱动方案要求它保持禁用。
- 禁止只截整个 GameView：地图、名字和血条会掩盖透明 RT，必须直接读取 `SceneCharStageRT`。

## 六、快速排查顺序

1. 核对主角、NPC、怪物的 ready/visible 日志，判断业务对象是否已创建。
2. 读取 `SceneCharacterRenderCase` 诊断中的 Camera、RT、RawImage、Renderer、active 和 in-frustum 数量。
3. 直接从 `SceneCharStageRT` 读取 alpha/lit 像素，不凭层级或 Inspector 猜测。
4. 静态真实 Prefab 显式渲染：若有像素，继续查相机调度；若仍无像素，再查材质、Layer、视锥和模型资源。
5. 核对 `SceneCharacterStageDriver` 是否存在、启用并执行，且离屏相机仍为 disabled。
6. 最后才检查 Addressables、模型地址与导入资产，避免把共享合成故障误判成三套模型资源同时损坏。
