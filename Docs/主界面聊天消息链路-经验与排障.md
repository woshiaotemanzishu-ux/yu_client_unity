# 主界面聊天消息链路：经验与排障

> 最后核对：2026-07-28
> 适用范围：`ChatController`、`ChatModel`、`MainUIChatView`、`MainUIChatItem`、`HudChatBar.prefab`

## 1. 用户可见症状

- 主界面长期只有一条本地欢迎语，服务端实时消息和历史缓存没有进入聊天栏。
- “系统 / 世界 / 仙宗”等频道徽标与正文叠在一起，文字从徽标下方开始。
- 同一账号下 Unity 的聊天明显少于老端，尤其缺少私聊、小跨服和百煞冲霄缓存。
- 单条模板高度固定为 50，而老端基础高度为 29；65 高的可视区因此只能稳定露出一条短消息。

## 2. 根因与证据

### 2.1 HUD 没有消费 ChatModel

旧 `MainUIChatView` 只实例化一条硬编码欢迎语，未订阅 `EVT_CHAT_MESSAGES_UPDATED`，也未读取
`ChatModel`。协议即使已经解析，主界面也不会更新。

### 2.2 GAME_START 缓存请求少于老端

老端 `ChatController` 在 `GAME_START` 依次请求：

1. `11010(channel=仙宗)`；
2. `11010(channel=私聊)`；
3. `11010(channel=世界)`；
4. 非开服第 1 天时，再请求 `11010(channel=小跨服17)` 与 `11010(channel=百煞冲霄20)`；
5. 空发 `11050 -> 11064 -> 11023`；
6. 最后插入本地欢迎语。

Unity 原来只请求仙宗和世界，因此消息少并不是展示错觉，而是启动请求确实缺失。

### 2.3 11010 的顺序和私聊结构处理不完整

服务端 `mod_chat_cache` 将新消息插入列表头，`11010` 的 wire 顺序是“新 → 旧”；老端倒序回放，
HUD 才能按“旧 → 新”向下排列。私聊缓存中的 `player_list` 同时包含发、收双方，不能只留下首个玩家，
否则无法确定会话对象和未读数。

老端还会把频道 20 的实时消息和缓存消息统一映射到小跨服频道 17；Unity 原来遗漏了这一步。

### 2.4 频道徽标不是普通左侧独立列

老端把频道图片嵌进富文本首行。正确效果是：首行正文从徽标右侧开始，而换行后重新回到消息左边缘。
Unity 保留独立 `Image`，同时只在 TMP 正文开头插入 `<space=46px>`，可以复现这项排版；直接给整段
正文增加左边距会让所有换行都右移，仍与老端不同。

## 3. 当前实现约束

- `MainUIChatView` 必须订阅 `EVT_CHAT_MESSAGES_UPDATED`，并从 `ChatModel` 重建两块现有内容区。
- 当前展示方案保持不变：普通频道在 `_box_chat_con`，系统频道在 `_box_sys_con`；是否合并或改 Tab
  属于独立策划决策，本链路修复不得顺带改变。
- HUD 每块最多保留末尾 30 条；普通区合并公开频道，不混入系统、私聊和仙宗答题频道 16。
- `11001` 与 `11010` 的频道 20 都映射到频道 17。
- `11010` 公共缓存必须按 wire 逆序落模型；私聊缓存也按逆序逐条调用 `AddPrivateMessage`，并以
  `is_read` 决定是否增加未读。
- 消息模板基础高度为 29，多行内容按 TMP `preferredHeight` 扩高；刷新后两块滚动区均落到底部。
- 本地欢迎语必须与老端 `ChatModel.ts` / `MainUIChatItem.json` 原文一致，不能另存一份近似文案。
- 老端常见 `<font color>`、`<color@n>`、链接和表情占位标签需要先转换为 TMP 可接受的最小子集，
  不能把原 HTML 原样交给 TMP。

## 4. 关键代码与生成入口

- 协议与启动请求：`Assets/Scripts/Module/Core/Chat/ChatController.cs`
- 消息分桶与 HUD 聚合：`Assets/Scripts/Module/Core/Chat/ChatModel.cs`
- 实时刷新与双区渲染：`Assets/Scripts/Module/Core/MainUI/Views/MainUIChatView.cs`
- 徽标、正文和富文本：`Assets/Scripts/Module/Core/MainUI/Views/MainUIChatItem.cs`
- 静态布局权威源：`Assets/Editor/UiCreator/MainUI/HudChatBarCreator.cs`
- 生成产物：`Assets/Prefabs/UI/MainUI/Regions/HudChatBar.prefab`

静态尺寸或组件结构调整后必须重新运行 `HudChatBarCreator.Generate()`，禁止只手改 prefab。

## 5. 验收

协议用例 `ChatCase.Run()` 至少覆盖：

- 11001 实时世界消息与频道 20 → 17；
- 11010 公共缓存旧新顺序、私聊双玩家与未读、频道 20 → 17；
- 原有私聊、喇叭、跨服开关、系统公告等聊天协议回归。

Prefab 用例 `MainUIChatHudCase.Run()` 必须克隆真实 `HudChatBar.prefab` 并验证：

- 普通区 / 系统区分流；
- 每区末尾 30 条；
- 徽标首行留位而非覆盖正文；
- 单行高度 29、多行动态扩高；
- 富文本转换、事件实时刷新、滚动到底部。

通过标志分别为 `CLIVERIFY chat ... pass=True` 与 `CLIVERIFY mainui-chat ... pass=True`。
