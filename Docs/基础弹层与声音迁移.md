## 二、物品使用与高阶装备弹层

### 2.1 数据流

```text
15010 背包全量 / 15017、15018 背包增量
  → BagModel 先落真实 BagGoods
  → ItemUseFlow 按 clientitemuse 配置筛选
  → 只有老端通用 15050 物品进入“使用”候选；专属页面/协议物品排除
  → 装备等待 15010 pos=1 权威快照，再按 equip_type 比较并只保留严格更高评分候选
  → CommonModule/ItemUseViewBind 展示
  → 确认后分别发送 15050 使用或 15201 穿戴
```

不得根据任务号、截图或物品类型写假触发；弹层只消费已经落入背包模型的真实物品实例。老端不存在“获得装备后自动穿戴”，因此登录和背包更新都不得代行一键装备；`15201` 只能来自玩家明确点击一键装备、详情穿戴或装备推荐确认。藏宝图、时装、选择礼包、称号、外观、影装等老端有专属分支的物品，在对应闭环完成前不得用通用 `15050` 冒充使用成功。

### 2.2 表现与生命周期

- 使用转换后的 `Assets/Prefabs/UI/Common/CommonModule.prefab`，不另造不可编辑的运行时面板。
- 展示在 `UILayer.Popup`，避免任务窗口切换中断其生命周期。
- 对齐老端：内容容器从下方 244 设计单位、透明度 0，在 0.3 秒内滑入并显现。
- 入场结束后追加轻微循环悬浮：以 Prefab 中 `_gp_con` 的静止位置为唯一基准，向上 12 单位后平滑回落，
  单程 0.8 秒；悬浮只叠加相对位移，不会覆盖人工调整的弹层位置。
- 入场、悬浮和自动使用倒计时由挂在 `ItemUseViewBind` 上的同一个 Unity Coroutine 驱动；不得使用独立
  `async Task + Task.Yield` 逐帧修改 RectTransform。装备按钮显示配置的倒计时，装备卡底部显示
  “合成可获更强装备！”。
- 动态补 `CanvasGroup` 时必须先 `GetComponent`，再使用 Unity 的 `component == null` 显式判断后
  `AddComponent`；不得对 `UnityEngine.Object` 使用 C# `??`，否则缺失组件代理会绕过补挂并在协程首帧抛出
  `MissingComponentException`，使入场、悬浮和倒计时同时中断。
- 名称颜色统一由 `LegacyUiColor` 映射老端 `ColorUtil` 的深色质量色。
- `clientitemuse.auto_use_sec > 0` 时，入场动画结束后才开始倒计时；缺字段时对齐老端 `ClientConfigDefaultVo` 使用 10 秒默认值，显式配置 0 则不倒计时。倒计时归零执行与按钮相同的真实使用/穿戴逻辑。
- 关闭、切场或重置必须递增演出版本，旧异步动画和倒计时不得操作下一件物品。

关键实现：

- `Assets/Scripts/Module/Core/Bag/ItemUseFlow.cs`
- `Assets/Scripts/Common/UI/LegacyUiColor.cs`

## 三、获得新技能组合弹层

### 3.1 触发语义

严格对齐老端 `CheckShortCutSkillOpenState`：

1. 登录后的第一份 21002 只建立快捷栏技能等级基线，不弹窗。
2. 后续 21002 中，某个快捷栏技能等级大于缓存等级时才排队展示。
3. 服务端以 `level=0` 表示未学习时，`0 → 1` 即“获得新技能”；普通升级也沿用老端同一弹层语义。
4. 多个技能同包变化时进入 FIFO 队列，前一个关闭后再展示下一个，不互相覆盖。

### 3.2 可编辑表现

- 复用转换产物 `Assets/Prefabs/UI/FunctionOpen/FunctionOpenModule.prefab` 中的 `FunctionOpenAutoView`。
- `FunctionOpenAutoView` 组件只负责组合演出；描述位置/尺寸/字号、技能图标尺寸、开场缩放、开场时长、点击延迟、自动关闭秒数和暗幕颜色均保存在 Prefab，可直接在 Inspector 调整。
- 标题、星光底、圆形技能底、技能图标和描述均读取真实资源/配置；配置中的 `<color@N>` 由 `LegacyUiColor` 转成 TMP 富文本，不在业务流里复制颜色表。
- 弹层根节点位于 `UILayer.Popup`；显示期间使用全屏暗幕，点击至少延迟 0.5 秒才可关闭，默认倒计时对齐老端语义。

关键实现：

- `Assets/Scripts/Module/Core/FunctionOpen/FunctionOpenAutoFlow.cs`
- `Assets/Scripts/Module/Core/FunctionOpen/FunctionOpenAutoView.cs`
- `Assets/Scripts/Module/Core/Skill/SkillManager.cs`
- `Assets/Scripts/Module/Core/Skill/SkillConfigs.cs`

运行态预览：进入 Play Mode 并登录主界面后，执行 `神霄/调试/UI弹层/预览获得技能`。菜单选取当前角色真实已学的主动技能，只绕过“再次升级”触发条件，不伪造技能配置或图标。

## 四、声音现状

截至 2026-07-27 的仓库审计结果：

- Unity `Assets` 下 `.mp3/.wav/.ogg` 数量为 **0**。
- `Assets/Scripts/Common/Audio/AudioManager.cs` 只是 Phase 0 骨架；项目中没有 `AudioManager.Init()` 调用，也没有任何 `PlayMusic/PlaySfx` 业务调用。
- 设置系统虽会调用 `SetVolume`，但 AudioSource 尚未创建，当前等价于全局无声。
- 老端 `cdn/resource/sound` 有 676 个音频文件，按“相对目录 + 去扩展名”合并后是 310 个逻辑声音；其中 293 个逻辑名同时存在多种格式。老端网页路径主要取 `.mp3`，原生 Conch 音效路径取 `.wav`，不能把所有格式当成不同声音重复导入。

因此获得技能弹层目前不调用 `double_box`：资源和统一声音服务尚未迁移完成时，单独在某个弹层写临时加载会形成第二套路径。

## 五、声音批量迁移方案

声音可以批量导入，建议独立一轮按以下顺序完成：

1. **生成清单并去重**：以 `sound/{category}/{name}` 为逻辑键，列出 mp3/wav/ogg 候选、旧端调用点、时长和大小；同键只产出一个 Unity 资源。短音效优先 WAV 源，背景音乐优先 MP3 源，缺失时按 OGG→MP3/WAV 的可用源回退。
2. **分类导入参数**：`scene` 设流式/循环音乐；`ui/skill/role/npc/novice_voice` 设短音效压缩和预加载策略；长语音单独管理。由 AssetPostprocessor 固化规则，禁止逐文件手改 Import Settings。
3. **统一 Addressables Key**：保持 `GameResPath.GetSoundPath(type, name)` 的 `resource/sound/{type}/{name}` 逻辑键；批量工具输出缺资源、重名和未引用报告，不新增第二套路由。
4. **补齐运行时服务**：`AudioManager.Init()` 必须幂等并接入已批准的启动位置；SFX 使用可并发 AudioSource 池，音乐切换负责释放旧 Clip，暂停/恢复、音量和静音继续消费现有 SettingModel。
5. **按旧端调用点恢复声音**：先恢复全局点击、场景音乐、战斗技能、获得/升级等高频声音；弹层只传 `type + logicalName`，不直接拼扩展名。
6. **验收**：编辑器、Android 和 WebGL 各跑一次；检查首次播放无明显卡顿、并发不截断、切场不叠音乐、音量设置可持久化、Addressables 无重复资产。

批量迁移会新增 Addressable 资源和导入规则，按项目规范应作为独立任务先确认清单、分组与启动接线，再落盘；本轮不自动执行。

## 六、验收清单

- 新获得普通可用物品后，右侧弹层出现，点击“使用”只发送一次真实请求。
- 新获得更高评分装备后，弹层显示金色上升箭头；低于或等于当前穿戴评分不出现。
- 物品弹层从下方淡入，动画期间不会被误点，关闭后下一候选可继续展示。
- 登录首包 21002 不出现“获得新技能”；后续真实 `0→1` 或升级才出现。
- 技能组合弹层暗幕、标题、技能名、图标、富文本描述、倒计时完整，连续获得多个技能按队列播放。
- 调整 `FunctionOpenModule.prefab` 上 `FunctionOpenAutoView` 参数后，无需改代码即可看到布局和时长变化。
- 当前代码与 Prefab 离线编译/序列化无错误；最终视觉尺寸和触发时机仍需活服 Play Mode 验收。

## 七、Prefab 样式权威与嵌套激活规则（2026-07-28）

### 7.1 获得技能弹层

获得技能弹层是 Prefab，但当前不是独立 Prefab 文件，而是
`Assets/Prefabs/UI/FunctionOpen/FunctionOpenModule.prefab` 内的 `FunctionOpenAutoView` 子 View。
以下节点是视觉样式的权威来源，运行时代码只填写文本、图片并控制显隐和演出，不得再次覆盖字号、颜色、
对齐、RectTransform 尺寸或位置：

- `title`：标题图片“获取新技能”，不是字体；通过 RectTransform 调整大小和位置。
- `skillLab`：技能名称的 TMP 字号、颜色、对齐和位置。
- `tips`：技能描述的 TMP 字号、颜色、行距、对齐、文本框尺寸和位置。
- `close_tip`：底部倒计时提示的 TMP 样式和位置。
- `icon`：技能图标的尺寸和位置。

资源加载不得调用 `SetNativeSize` 覆盖 `title` 或 `icon` 的人工尺寸。需要预览时，在 Play Mode 使用
`神霄/调试/UI弹层/预览获得技能`；保存 Prefab 后无需修改业务代码。

### 7.2 物品使用/穿戴弹层

物品弹层位于 `Assets/Prefabs/UI/Common/CommonModule.prefab` 的 `ItemUseView` 子 View，实际可见内容
全部位于 `ItemUseView/_gp_con`。转换快照曾把 `_gp_con` 保存为 inactive，导致业务日志已经输出
`[ItemUse] show ...`，但画面完全不可见。`_gp_con` 现在必须在 Prefab 中保持 active，运行时也做防御性
激活；其 RectTransform 是弹层静止位置的权威来源，入场动画只从该位置下方 244 单位滑入，不覆盖人工位置。
入场完成后的循环悬浮同样以该静止位置计算，关闭或切换候选时通过演出版本自动终止，旧动画不得回写或
干扰下一件物品。

可直接在 Prefab 中调整 `_gp_con`、`name_label`、`item_group`、`enter_btn/enter_btn_text` 和
`bottom_label`。转换或重烘焙后的 View 不能只验证 `BaseView.Show()` 激活了根节点，还必须检查所有可见内容
祖先节点是否 active；关闭态快照里的 inactive 容器不得未经语义判断直接保留为运行态默认值。
