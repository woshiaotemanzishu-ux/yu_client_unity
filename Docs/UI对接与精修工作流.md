# UI 工作流

UI 工作不再由一条流程包办。先选择当前阶段，同一轮默认只执行一种模式。

| 用户目标 | Skill | 本轮终点 |
|---|---|---|
| UI 对接、先跑通、补按钮、逻辑、协议 | `ui-function-fast-pass` | 最小功能组件 + 代码 + 定向编译 |
| 修布局、图片、模型、特效 | `fix-view` | 指定视觉差异修复并复验 |
| 巡检、验收、最终收口 | `audit-game-ui-route` | 真实运行证据与精确缺陷/完成结论 |
| 首次转换且无 Prefab | `convert-module` | 首次 Prefab + Bind/View 落地 |

## 总原则

- 用户本轮目标和时间预算决定阶段，不能把最终验收要求前置到开发。
- 简称固定为：`UI 对接=功能快接`、`UI 精修=视觉修复`、`UI 验收/UIDAudit=最终验收`。
- 已有 Prefab 不重转；缺功能载体只补最小可点击组件，完整视觉以后处理。
- 老端同账号、同状态运行结果仍是最终验收权威，但只在最终验收阶段完整采证。
- 阶段外缺口记录为 `function-pending`、`visual-pending`、`runtime-pending` 或 `blocked`，不递归展开。
- 切换模式前先结束当前模式并报告，不能同时加载多套完成标准。

## 时间参考

小型单 Tab 的功能快接参考：盘点 20 分钟、实现 30 分钟、编译 5 分钟。连续 10 分钟没有当前阶段产物即停止纠偏。视觉精修和最终运行验收单独计时，不混入功能实现时间。
