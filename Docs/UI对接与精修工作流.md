# UI 对接与精修工作流

“UI 对接”和“UI 精修”是本项目对同一套端到端工作的两个称呼，不是两个阶段、两套任务或两个完成等级。用户使用任意一个词时，都执行完整流程；不能把“对接”理解成只接协议和点击，也不能把“精修”理解成只调位置和像素。

## 固定流程

1. 用 `audit-game-ui-route` 建立页面控件树，先列同层清单，再沿一条分支深度优先点到叶子。
2. 对照老 Web 客户端与 Unity 的同账号真实运行态，核查功能、即时状态、2D视觉、3D模型/特效、资源闭包、cold/warm 性能、关闭重开和返回链。
   - 当老 Web 与 Unity 使用同一账号，且服务器是单会话或后登录会踢前登录时，禁止两端同时在线做对照。必须在相同 viewport、角色、页面和状态下顺序采证：先在一端截图并完整退出/确认断线，再登录另一端复现。被踢端若只剩场景/HUD 残影而 `RoleModel` 或协议状态已清空，该证据无效；cold/warm 时间也必须各自在有效登录会话内测量。
3. 目标尚无可编辑 Prefab 时，仅首次调用 `convert-module` 落地；已有 Prefab 时调用 `fix-view` 增量修改，禁止为精修重转模块或全量覆盖。
4. 修复后返回原路线，用真实 `GraphicRaycaster→PointerClick`、真实拖动、协议/状态断言、截图/diff和资源幂等证据复验。
5. 只有全部适用叶子通过四层完成定义，父页面才可标记 `done`；用户新截图可以推翻旧结论并把路线回卷为 `defect`。

## 共享组件优先与状态矩阵

页面控件清单之后增加“组件依赖清单”。视觉结构、交互语义和数据形状相同、仅输入数据不同的物品格、详情卡、按钮组、页签和列表项，必须引用同一共享 Prefab/View；宿主页面只传数据、状态和回调，禁止复制节点树、页面专用坐标或重复状态逻辑。

共享组件先于整页复验。每个组件按适用项覆盖特效开/关、1/2/3 项整体居中、短/长文案且不误换行、单/双按钮居中、充足/不足、选中/未选中、空/有数据和目标 viewport。组件局部截图、Prefab/GUID 身份链及几何断言通过后，再沿原页面路线做一次整页点击、弹窗、返回和截图复验；这能减少重复调试，但不降低真实 Web 收口要求。

修改共享 Prefab/View 时，先用 GUID、序列化引用和代码调用点列出全部直接消费者，但运行态采用代表性抽查而不是逐页穷举。先按直接/嵌套实例、展示/交互、空/有数据、特效开/关、宿主缩放/viewport 等实际差异分组；默认验证本次目标页，并从每个发生实质差异的组抽一个独立宿主页，常规总量控制在 2～4 页。根组件、序列化 Bind 或生命周期有改动时，样本必须包含一个高频既有页面。抽样失败就扩大同组检查并继续修共享根因；只有删改公共 API/字段、整体换引用或连续抽样失败才做全量消费者核对。证据中记录“消费者总表、分组、抽样理由、结果”，不能只写引用数量，也不能因为引用很多就不检查。

特效状态矩阵必须从老端实际调用点记录 `effectName/parent/position/scale/rotation/loop/renderSize`，不能只确认资源名。第一步先区分效果属于页面、共享格子还是模型骨骼；同一资源在不同宿主允许有不同参数，不能跨归属补效果。旧端显式 `scale` 是转换语义的输入，但 Unity 最终倍率必须结合转换后 Prefab 的基准尺寸、宿主缩放、profile 与共享通道 `instanceFactor` 做映射，并用隔离后的真实画面校准，禁止直接把旧端数字复制到所有宿主。验收应隔离目标 Handle 后读取该实例的 RenderTexture 非透明像素与 alpha 包围盒宽高，并按预期宿主尺寸判断是否形成可辨认的二维足迹；Handle 存在、贴图已绑定或只有几个亮点一律不能算特效可见。阈值由目标资源和宿主基线确定，不使用全项目通用的低像素常量。

动态特效固定按“归属 → 调用参数 → 资源驱动链 → 宿主几何 → 裁剪/层级 → 时间变化 → 生命周期 → 代表消费者”检查。资源驱动链必须从 Animation/ParticleSystem 曲线追到材质属性、shader 分支和最终采样值；曲线写 `_BaseMap_ST` 而材质仍选择 `_MainTex_ST` 时，即使 `Animation.isPlaying=true` 也只能得到静态首帧。动态通过必须针对同一隔离 Handle 保存两个不同时间点的画面、时间或属性推进值和像素差，单张截图只回答“这一帧在哪里”，不能回答“它是否在动”。

共享 Camera/RenderTexture/RawImage 会脱离宿主原有 UGUI 层级。列表物品、滚动卡片等实例除了裁自己的宿主矩形，还要与有效祖先 `RectMask2D/Mask` 求交；验收固定覆盖完整可见、部分进入裁切、完全滚出后目标 alpha 为零三态。不能因为物品图标已经被 `Viewport` 裁掉，就假设页面根共享 RawImage 中的特效也会自动消失。

schema 5 路线台账新增 `shared_component_identity` 和 `component_state_matrix` 两个门禁，证据分别写入 `component_evidence[]` 与 `component_state_evidence[]`。历史 schema 4 台账保持兼容；用户新截图推翻旧结论时，重开受影响组件变体、目标路线叶和所选代表消费者并补新门禁，不机械重开全部直接消费者。

## 真实 Web 对比与构建节奏

1. 老 H5 与 Unity 的主视觉证据来自真实浏览器包。常规对比使用后台 Headless Playwright/Puppeteer，固定 `720×1280` 移动端 viewport，并补一个 Web 宽屏 viewport；保存 old、unity、overlay 和 diff。Computer Use、前台手工点击和 CLI 合成截图不得作为日常主对比链，除非用户本轮明确授权。
2. 同账号单会话必须顺序采证：老 H5 完成路线、截图并确认断线后，再登录 Unity Web 复现。Canvas 点击每次动态读取画布矩形；可使用开发态只读桥查询 Bind 的屏幕 Rect 和 ready 状态，但最终交互仍由浏览器发送真实指针事件。
3. 每个页面收口前必须对照与当前源码精确匹配的真实 Web 包。报告至少记录 Git commit、未提交修改指纹、Player 哈希、catalog 哈希和页面路线；任一不匹配都拒绝比较，历史截图不能继承为当前 `web-verified`。
4. 首次基线或 Addressables 状态不可信时完整构建内容+壳。修改 C#、Web 模板、插件或 Player 设置时重打壳；仅修改已登记的 Addressable Prefab、图片或配置时，在已验证基线上只构建内容。整包按逻辑批次执行，不按单个像素或按钮执行；页面 `done` 前至少有一份当前真实包报告。
5. 对比工具只减少 Computer Use、手工点击、截图整理和重复登录，不消除 Unity 构建时间。当前壳实测预算按 12～25 分钟计，构建等待期间只做下一页老端基线、资源映射等只读工作，不修改正在构建的输入。

## 执行纠偏与页面吞吐

- 角色界面等长任务保持完整页面/控件粒度，但实现按共享结构批量完成；逐叶台账不等于逐叶手工重复截图。
- 选择一个页面后，该页全部控件、条件状态、弹窗、滚动、模型/特效、声音、返回、重开和适用事务都进入本批范围；完成或明确 `blocked` 前不换页。
- 执行中每约十分钟检查一次：当前动作是否仍直接推进选定页面、对比是否来自最新真实 Web、是否把基础设施/Git/证据整理混入页面工时、是否在无新信息地重复验证。发现偏航立即停下并纠正。
- 每个页面先修共享 Prefab、绑定、初始化和一条代表路径，再批量覆盖同构控件；真实 Web 对比后只改资源/Prefab的尾项优先走内容构建，C# 缺陷汇总后一次修完再重打壳。
- 页面可见效果是主要产出指标。普通页面不复制数百行专项验收 Case；通用打开、点击、滚动、截图和几何断言应数据化复用，专项代码只用于独特协议、场景生命周期或渲染机制。

### 工时基准与节约判断

2026-08-07 共鸣模块从首次落地到首轮人工可看结果的实测总耗时为 4 小时，整体效果可接受，但人工复查仍发现部位特效框、材料整体居中和共享详情布局三类遗漏。后续特写先证明“已挂特效并有少量 RT 像素”不能代表完整效果，最新复查又纠正了特效所有者，并暴露共享物品格根组件丢失导致背包回归：这说明参数核对必须晚于归属判定，共享组件修改必须同时做根身份检查和跨页面代表抽查。该 4 小时作为当前复杂页面基准；由于当时没有分阶段计时，不据此虚构节约百分比。

2026-08-08 品质流光又经历两次人工回卷：第一轮只恢复动画资源和倍率，因漏掉老端每格私有 RT 边界而形成整页巨大折线；第二轮框的位置已经正确，但材质没有消费动画实际写入的 `_BaseMap_ST`，并且页面根共享 RawImage 绕过了背包 `Viewport`，所以仍是静态框且滚出后压到底栏。修正材质驱动链并把实例裁切与祖先遮罩求交后，用户最终运行确认通过。以后节约时间的关键是在首次实现前完成“归属/参数/驱动属性/材质分支/宿主/祖先遮罩/双时间点/关闭重开”八项特效契约，而不是先把单帧位置调得接近再逐轮补根因。

后续每个页面至少记录六类时间：老端事实/控件与组件清单、共享组件实现、页面业务与协议、组件状态矩阵、整页 Editor/CLI 回归、真实 Web 构建与对比；等待构建/导入单独记录，不和有效修改时间混在一起。返工要关联到“漏枚举、漏共享身份、漏消费者抽样、漏状态变体、实现缺陷、证据过期或环境等待”之一。相同共享组件只计一次实现与组件级回归，宿主按使用形态保留代表路径，不逐页重复整套验证；如果下一页仍在重复修改同一节点树或相同坐标，直接视为流程未生效，而不是正常页面工时。

节约时间的判断依据不是少点几个叶子，而是：同类缺陷是否从多页重复修改收敛为一次共享修复、同一状态是否只生成一份可复用组件证据、C#/Prefab/Web 构建是否按逻辑批次执行、人工复查是否不再发现状态矩阵内的遗漏。真实 Web 最终收口、资产事务授权和独特 3D/特效像素门禁不能为了缩短工时跳过。

## Skill 协作关系

| Skill | 在统一流程中的职责 |
|---|---|
| `audit-game-ui-route` | 统一入口、建树、逐叶验收、证据和最终收口 |
| `convert-module` | 仅处理尚无可编辑 Prefab 的首次转换落地 |
| `fix-view` | 对已由 Prefab 接管的页面做视觉、功能和运行态增量修复 |

具体硬闸和执行细节以三个 Skill、[人物与设置面板对标经验](人物与设置面板对标-经验与排障.md)及各模块运行态对标报告为准。
