# 通用奖励飞行动画

## 事实源与职责

老客户端权威实现位于 `yu_client/h5/src/commonController/MainUIController.ts` 的 `EventName.REWARD_FLY`、`ShowItemMove` 和 `ShowDiamond`。Unity 对应入口为 `Assets/Scripts/Module/Core/MainUI/RewardFlyService.cs`。业务页面只在权威成功回包后传入奖励三元组和起点；服务负责奖励分类、目标定位、动画、到达反馈及清理，不允许各页面再复制一套飞图坐标和生命周期。

这里的“权威”首先指老客户端同状态下玩家最终看到的运行结果，而不是某一份源文件、运行树结构或转换方案。源码和运行树负责解释，Unity 架构负责实现；若二者与最终像素、时序或生命周期冲突，修改 Unity，不修改验收标准。本次灰色圆片问题最终通过直接复用老端特效宿主的最终 RGBA 序列解决，正是因为通用粒子转换和共享 RT 已无法无损恢复老端每实例合成边界。

## 路由与时序

奖励先经 `GoodsModel.GetMappingTypeId(style, typeId)` 得到实际物品 ID：

| 实际 ID | 视觉 | 目标 |
| --- | --- | --- |
| `34` | `ui_bangyu_2` | 顶部货币类型 0（元宝） |
| `35`、`36020001` | `ui_bangyu_1` | 顶部货币类型 1（绑元） |
| `31` | `common/com_gold` | 顶部货币类型 2（金币） |
| 其他 | 84×84 真实物品图标 | 底部 `MainFuncIconItem.Res == "bag"` |

普通物品按原奖励索引每项错峰 120ms，直接飞行 750ms。货币默认生成 5 个粒子；数量大于 15 时生成 `min(ceil(count/3), 20)` 个。每个粒子先用 400ms 在起点 ±100 逻辑像素内散开，再用 `700ms + index×50ms` 飞向对应顶部货币图标；元宝/绑元沿用老端特效倍率 14，金币图片同步旋转并缩小到 0.4。

老端 `ShowDiamond` 的结构不是“显示 5 份就实例化 5 套粒子”。`AddUIEffect` 默认启用缓存，5 个同名 `effect_box` 的资源、位置、倍率和 100×100 宿主尺寸相同，命中同一个 cache key，因此只保留 **1 个 `UIEffectInfo/Scene3D/Particle/RenderTexture` 动态源**；每个飞行节点只复制一张读取该 100×100 动态 RT 的二维 `Image`。该拓扑事实仍需用于相位、随机形态和重叠节奏验收，但它不自动解释所有可见缺陷。

2026-08-09 已把这两个货币资源从通用 `UIEffectStage` 合成链中单独拆出。原因不是资源缺少粒子，而是同一旧特效同时混有覆盖、Alpha 与 Additive 子材质；转换后的共享全屏 RT 已经丢失“每实例 100×100 最终合成”的信息，再换一个全局 RawImage shader 无法可靠反推。Headless 老 H5 现在直接读取真实 `UIEffect.render_texture` 的 RGBA：每个资源按声明的 60fps 时间轴采 120 帧、每帧 100×100、完整保留透明像素的 RGB 与 Alpha，再打成带 2px 防串色边的 12×10 无损 PNG 图集。它不是页面截图，也不包含按钮、背景或轨迹。

Unity `RewardFlyService` 每批货币只加载并推进一份图集时钟，N 个飞行节点各持一张 `RawImage` presenter，使用普通 Alpha 合成读取同一帧；外层节点负责散射、飞行和缩放，内层节点保留老端随机 `0.7～1.2` 缩放与随机旋转。由此同时恢复 `1 个动态源 → N 个显示副本`、100×100 私有边界、原始透明度和双层变换，且不全局修改仍然正常的顶部、场景、技能或“变强”特效。

权威采集证据位于 `output/ui_route_audit/2026-08-09_reward_fly_rgba_capture_03/legacy_rgba/`。`ui_bangyu_1` 原始 RGBA / 图集 SHA-256 分别为 `4babc63855e7ed965c5c54fee662aec3417e5e57c897e2f23953ae0726031b5b` / `6e595023d30c3cb0aefb0635aeadb54a67233fea6f59d48ec860a5a403cbfd73`；`ui_bangyu_2` 为 `21b2965607f5bf58316714d6094bc1aa84af6e564349918e585d302b3763eba7` / `d823b4d6b5e5c36f5e313e38b7834bcc91dfd7750209351ee8dd493d67abd4e3`。抽样帧已逐像素验证图集单元等于老端 RT 字节（仅做坐标原点翻转）。

## 坐标与生命周期合同

- 起点和终点都先取得真实控件世界坐标，再换算到 `UILayer.Top`，禁止写固定屏幕坐标。
- `MainFuncIconItem.RewardFlyTarget` 与 `MainUIMoneyItem.RewardFlyTarget` 暴露实际图标 RectTransform；货币类型由 `MainUIMoneyItem.MoneyType` 提供。
- 服务返回独立 `Handle`。自然结束逐粒子销毁节点并释放共享 RGBA 序列；页面关闭、异常或主动取消调用 `Dispose()`，异步加载后到的图集也必须立即释放。
- 动画只表达已经确认的奖励结果，不能在点击、请求发出或本地乐观状态时启动。

## 验收

至少在同一真实运行批次验证：普通物品飞向背包；元宝、绑元、金币分别飞向正确顶部槽；`ui_bangyu_1/2` 不出现灰片、透明区实心化或图集串帧；100×100 足迹、数量、大小、方向、错峰、起终点、共享相位、重叠顺序、双层变换和到达反馈均与老端时间序列一致。Editor 与当前 WebGL 都必须采同时间点；飞行期间关闭页面无残留，正常结束后临时节点、presenter 与序列 Handle 为零。原始图集逐像素一致、静态编译或单帧都不能替代最终 Canvas 动态证据。

2026-08-09，用户在当前 Unity 真实领取流程中复验后确认本次可见奖励飞行效果“好了”。该证据关闭此前截图中的灰色实心圆片/错误合成这一精确缺陷，并证明“老端最终 RGBA → Unity 普通 Alpha presenter”的兼容路线可落地；它不自动证明未单独观察的另一货币变体、飞行中关页清理或同批 WebGL，也不把成就整页升级为 `done`。
