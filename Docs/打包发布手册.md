# 打包发布手册(2026-07-13,Web 打包战役收官版)

一页说清:怎么打包、怎么发布到 jzy、怎么验收、出了问题看哪。深度背景/坑账见记忆档案 packaging-plan-2026-07。

## 〇、心智模型
- **壳**(Builds/WebGL:引擎 wasm+data+loader+页面)和**内容**(ServerData/WebGL:Addressables bundle+catalog)是两条线。
  - 只改 C# 代码 → 重打壳;只改资源/配表 → 重打内容(客户端启动自动感知,不用发壳);都改 → 都打。
  - **资源/配表入库后必须跑一轮内容构建**——光打壳会"key 不在 Addressables"刷屏(铁律,踩过)。
- **CDN 地址是部署配置,不烧壳(2026-07-13 起)**:WebGL 启动时按优先级取 `?cdn=` URL 参数 > 壳同目录 `boot_config.json` > AppConfig 烧包默认值(=本地开发 `http://127.0.0.1:8090/res`)。
  - **换 CDN=改服务器上 `web/boot_config.json` 一个文件,零重打包**(格式:`{"cdnBaseUrl":"http://223.109.142.26:89/cdn"}`,可选 astcCdnBaseUrl/gmApiUrl;nginx 已配 no-cache)。
  - 本地联调:SimCdn 目录没有 boot_config.json → 自动落到烧包默认,什么都不用改;临时指任意源:页面 URL 加 `?cdn=http://...`。
  - 实现:`Framework/Config/BootConfig.cs`,AppLauncher 在 Addressables 初始化前调用;失败静默走默认,绝不挡启动。

## 二、CLI(编辑器必须关着;PowerShell 对 Unity.exe 不等待,用 Start-Process -PassThru 盯 PID)
```
# 一条龙(内容+壳，独立工作区必须显式指定 WebGL):
Unity.exe -batchmode -buildTarget WebGL -projectPath . -executeMethod Shenxiao.EditorTools.Packaging.PackagingBuild.BuildAllWebCli -logFile Temp/build.log
# 只打壳(改代码用,12~25 分钟): -buildTarget WebGL ...PackagingBuild.BuildWebShellOnlyCli
# 只打内容(改资源/配表用,1~15 分钟): -quit -executeMethod ...PackagingBuild.BuildContentMenu
# Android 一条龙(启动参数加 -buildTarget Android): ...PackagingBuild.BuildAllAndroidCli(内容+流式小包)
# Android 整包一条龙(同上加 -buildTarget Android):  ...PackagingBuild.BuildAllAndroidFullCli(内容+整包)
```
异常退出会留僵尸 `Temp/UnityLockfile`,确认无 Unity 进程后删掉再跑。

> 只打壳依赖当前工作区已有与线上内容匹配的 Addressables 构建状态。全新隔离 worktree 不得直接用 `BuildWebShellOnlyCli` 发布：2026-08-03 实测会把不完整的本地 catalog 带入 `StreamingAssets/aa`，导致启动 key 缺失。应使用持续构建工作区，或完整构建并成套发布内容+壳；禁止手工拼接不同次构建的 `StreamingAssets/aa` 和 player 作为正式产物。

## 三、发布到 jzy(入口 **http://223.109.142.26:89/web/**,站点根 /www/wwwroot/download_unity)
服务器目录:`web/`=壳(index.html/Build/TemplateData/**boot_config.json**),`cdn/`=内容(WebGL/…)。URL 即目录:`:89/web/...` 与 `:89/cdn/WebGL/...`。
```
# 发内容(纪律:先 bundle 后 catalog):
tar cf - -C ServerData --exclude="WebGL/catalog_live.*" WebGL | ssh jzy "tar xf - -C /www/wwwroot/download_unity/cdn"
tar cf - -C ServerData WebGL/catalog_live.bin WebGL/catalog_live.hash WebGL/build_manifest.json | ssh jzy "tar xf - -C /www/wwwroot/download_unity/cdn"
# 发壳(不会覆盖 boot_config.json,它只在服务器上):
tar cf - -C Builds/WebGL . | ssh jzy "tar xf - -C /www/wwwroot/download_unity/web"
```
- 上述二进制 pipe 写法适用于 bash/WSL，**不得直接在 Windows PowerShell 中运行**，PowerShell 管道会损坏 tar 字节。PowerShell 下先生成本地 tar，再 `scp` 到服务器，服务器先 `tar tf` 校验后再解包；部署后对 wasm/catalog 与本地做 SHA-256 比对。
- 换 CDN 地址:只改服务器 `web/boot_config.json`,不重打包。
- GC:本地跑 菜单[通用/GC清旧内容](或同逻辑脚本)后再上传;服务器侧等所有客户端拿到新 catalog 后再清旧包。
- nginx 定制在 `/www/server/panel/vhost/nginx/extension/223.109.142.26_89/unity.conf`:boot_config no-cache/.gz 直出 Content-Encoding(loader 硬要求)/wasm 流式编译 Content-Type/bundle immutable/catalog no-cache+动态 gzip(10.3MB→4.3MB)。改完 `nginx -t && nginx -s reload`。
- 端口:站点只绑 **89**(80 已按要求让出)。⚠从部分外网测 89 不通(疑机房安全组),打不开就去云控制台放行 89。

## 五、Android(2026-07-13 双包型已通)
- **两种包并存,菜单分开**:流式小包(Shenxiao.apk ~65MB,资源走 CDN 按需下载落盘)/整包(Shenxiao_full.apk ~935MB,资源全内置,免服务器且零启动下载——流式包的"启动黑屏等下载"在整包上不存在)。**不搞代码热更框架**(资源热更=Addressables 本来就有:改内容→传 cdn/Android→客户端自动感知不重装;改 C#=重发 APK;整包无热更,重发整包)。
- CLI:`-buildTarget Android -executeMethod ...BuildAllAndroidCli`(内容+小包)/`...BuildAllAndroidFullCli`(内容+整包);**CDN 地址构建期注入**(小包=AndroidCdnBaseUrl 常量;整包={streaming}/cdn 令牌→ResCdn 解析为包内 StreamingAssets 路径;构完都自动还原 AppConfig)。
- 发布:内容 tar 到 `cdn/Android`(先 bundle 后 catalog,同 Web);APK 放 `web/Shenxiao.apk` 供手机直接下载安装(http://223.109.142.26:89/web/Shenxiao.apk)。
- Android 内容=移动纹理格式(882MB,比 WebGL 的 DXT 还小),**无需 ASTC 变体专项**(那是 Web 跑手机浏览器才要的)。
- 构建报告显示 1214MB 是把符号目录算进去了,真实 APK ~65MB;构建成功后偶发关闭期崩溃(退出码1,良性,看日志"壳构建 Succeeded"为准)。

### Android 模拟器视频花屏排查（2026-07-28）

- Unity 官方不把 Android 模拟器列为受支持运行环境，视频结论必须以真机为准：
  <https://docs.unity3d.com/cn/2023.2/Manual/android-requirements-and-compatibility.html>。
- 当前创角视频均为 Android 常规的 H.264 / yuv420p；实录花屏时 logcat 连续出现
  `OMX.qcom.video.decoder.avc`、`DynamicANWBuffer failed`，同时图形设备为 `goldfish_vulkan`。这是模拟器
  “硬解码输出表面 → Vulkan 虚拟显卡”桥接失败，不是 MP4 文件损坏。
- 先在模拟器设置中把图形渲染切为 **OpenGL/兼容模式**，彻底关闭并冷启动模拟器，再清进程重开游戏；
  不要只热重启应用。若模拟器仍花屏而真机正常，按模拟器限制处理，不为它全局禁用 Vulkan。
- 新视频继续统一交付 H.264、yuv420p、720×1280，并用 `adb logcat` 查看平台解码器错误。Unity 的平台视频
  兼容说明：<https://docs.unity3d.com/es/2019.3/Manual/VideoSources-FileCompatibility.html>。
