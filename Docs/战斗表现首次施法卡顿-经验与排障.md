# 战斗表现首次施法卡顿：预加载与混合模型排障

> 状态：已实现，离线编译通过，等待冷启动活服复验
>
> 最后核对：2026-07-27
>
> 适用范围：主角首次普攻、职业技能、刀光粒子，以及 `model_replacement.json` 驱动的新旧混合角色模型

## 一、用户可见症状

- 角色第一次普攻或第一次使用某个技能时，动作/刀光会停顿或晚出现一下。
- 同一局内第二次再用相同技能通常正常。
- 问题在新 Art 角色与旧动作混用时更明显，容易被误判成单纯的粒子参数或 Shader 问题。

“只卡第一次、之后正常”优先说明冷路径落在了战斗帧，不应先调整粒子速度、播放时长或动作节拍。

## 二、最终根因与证据

本次是三条冷路径叠加，不是单一资源：

1. `MainRoleAgent.PlaySkillAsync` 在攻击已触发后才准备动作；`EffectBinder.AttachOneByKey` 也在播放时才加载并实例化技能 Prefab。
2. `LegacyPreloadService.PreloadGameStartAsync` 原来只预热主角 `idle/run`，没有覆盖当前职业的普攻、主动技能动作和对应 `skills_effect`。
3. 更大的尖刺来自混合模型：如 `role/1111` 只替换了 `idle/run/...`，没有替换 `attack/skill*`。第一次攻击时，`ReplaceableRoleModel.EnsureOldModel` 才临时拼装整套旧衣服、头、武器、常驻特效和动作；后续复用 `_oldModel`，所以不再卡。

老客户端 `E:/GitProject/yu_client/h5/laya/assets/resource/config/client/ConfigPreloadResList.json` 已明确把职业普攻动作和 `effect_male_normal_atk01_001` 等刀光资源放入包内预加载清单。Unity 迁移时保留了“全清单后台补齐”，却遗漏了当前职业首战资源的前台最小预热。

## 三、最终方案与数据流

```text
ConfigSkillUI 当前职业技能表
        +
ConfigCareerSkillMovies 动作/粒子表
        ↓
SkillVisualWarmupPlan（去重后的动作 + skills_effect key）
        ↓
GameStart 资源阶段：下载/加载并保留当前职业所需资产
        ↓
MainRoleFlow 角色可见前：
  - 纯旧模型：补齐 run/attack/skill clip
  - 混合模型：预建新动作实例；未替换动作预建一套旧模型兼容分支
        ↓
首个战斗帧只切换已准备实例并播放已缓存粒子
```

关键原则：

- 预热范围由配置生成，不硬编码职业或技能 ID；技能表调整后自动跟随。
- 只预热当前职业会使用的资源，不把老端 `package_common_res` 数千条资源重新阻塞到启动阶段。
- 混合模型预建必须保持当前 `idle` 仍为激活画面，不能因为预热造成进场闪模。
- 资源加载与实例准备前移到进场加载阶段；允许加载阶段略增，但禁止把成本留在第一次挥刀帧。

## 四、关键代码入口

- `Assets/Scripts/Module/Core/Skill/SkillMovieConfigs.cs`
  - `BuildCareerWarmupPlanAsync`：按当前职业配置生成动作/粒子最小集合。
- `Assets/Scripts/Module/Core/Preload/LegacyPreloadService.cs`
  - `PreloadGameStartAsync`：把职业动作、技能粒子与动作替换 Prefab 纳入既有 GameStart 预热阶段。
- `Assets/Scripts/Common/UI3D/ReplaceableRoleModel.cs`
  - `PrepareActionsAsync`：静默预建新动作实例与旧模型回退分支，不改变当前显示动作。
- `Assets/Scripts/Module/Core/Scene/MainRoleFlow.cs`
  - 角色正式交给 `MainRoleAgent` 前完成首战动作实例准备。
- `Assets/Editor/CliVerify/Cases/SceneMixDriverCase.cs`
  - 断言预热后 `run` 与 `attack` 已准备、`idle` 未被抢台，随后切换复用缓存。

## 五、边界与明确不做

- 不使用 `Shader.WarmupAllShaders()`：它会把无关变体一次性编译，启动尖刺和内存不可控。
- 不恢复老端全部 4453 条打包清单为启动阻塞下载；大清单仍只用于进游戏后的后台缓存补齐。
- 本轮没有新建第二套资源加载器，也没有为单个刀光建立专用相机或预览流程。
- 当前消除的是已证实的资源冷加载、旧模型首次装配和动作首次加载。如果冷启动复验后只剩很小的单帧 GPU 尖刺，应使用 Unity Profiler 确认具体 Shader Variant，再做定向变体集合或特效池预热，不能凭感觉全局 Warmup。

## 六、验收方法

必须冷启动验证；同一 Play 会话的第二次施法已经命中缓存，不能作为验收样本。

1. 停止 Play Mode，等待脚本编译完成后重新进入游戏。
2. 使用一个此前未施放过的普攻/主动技能，观察首刀动作与刀光是否同步、主线程是否出现明显停顿。
3. 分别验证一次普攻和四个当前职业技能；纯旧模型与 `model_replacement` 混合模型各验一个角色。
4. 确认进场待机没有闪成 `run/attack`，切图复用同形象时也不应改变当前动作。
5. 若仍卡，Profiler 依次检查 `Object.Instantiate`、`Shader.CreateGPUProgram`、纹理上传和 GC；先保留采样证据再决定特效池或定向 Shader 预热。

离线闸门：

- `dotnet build Shenxiao.Module.Core.csproj --no-restore`
- `dotnet build Shenxiao.Editor.csproj --no-restore`
- `SceneMixDriverCase`：预建状态和新旧模型切换断言。

## 七、后续快速排查顺序

1. 先确认是否只发生在第一次；若每次都卡，优先查每次重复实例化/销毁、GC 或业务等待。
2. 查 `SkillVisualWarmupPlan` 是否包含实际收到的 `skillId` 对应动作与粒子。
3. 查 GameStart 预热日志是否存在资源缺失/转换失败。
4. 查当前衣服动作是否命中 `model_replacement.json`；未命中时确认 `_oldModel` 是否已经在进场阶段生成。
5. 最后才查 Shader Variant；禁止用改播放速度、延迟特效或全局 Shader Warmup 掩盖冷加载。
