# 技能点击与范围规则：经验与排障

> 状态：生效
>
> 最后核对：2026-07-28
>
> 适用范围：主界面技能按钮、手动/自动施法、PvE 怪物选取与 `20001` 目标列表

## 一、用户可见症状

以下现象通常不是按钮 Prefab 坏了，而是技能业务边界或范围配置消费错误：

- 主界面技能图标可见，但普通自动战斗期间点击没有反应。
- 手点一个没有锁定目标的技能，角色突然追向远处怪物。
- 普攻总要贴到怪物很近才放，表现像“乱走、乱放”。
- 所有群攻看起来都按圆形判定，直线和扇形技能没有方向性。
- 技能描述写“直线”或“扇形”，运行结果却不同。

`HudSkillBar.prefab` 的技能背景图已经具备 Raycast，`MainUISkillItem` 也会在 `SetData` 时幂等绑定点击。本轮问题的根因不在 Bind 或点击热区。

## 二、老端权威证据

权威实现位于老客户端：

- `h5/src/mainUI/MainUISkillItem.ts`：技能按钮只在 `RoleManager.GetMainRoleDepositState()` 为真时拦截；普通 `AutoFight` 不是该条件。
- `h5/src/skill/SkillManager.ts`：`UpdateAttackDistance` 先取 `distance`；当 `GetAoeMode()==1` 时再加 `area`，最后使用 `max(100, skill_distance*0.8)`。
- `h5/src/scene/Scene.ts`：手动无点击目标时不会全场抓最近怪并自动追击，而是进入空目标释放边界。
- `h5/src/scene/fight/FightController.ts`：`range/distance/area/num` 决定目标几何、数量和 `20001` 目标顺序；`target_hiter` 强制置首。

Unity 修复前有三处偏差：

1. `MainUISkillItem` 把普通 `AutoFightState` 当成托管态，直接吞掉手动点击。
2. 接敌距离固定为 `distance*0.8`，漏掉圆形技能的 `area`。
3. 手动无目标时从整个 `SceneManager` 找最近怪并自动接近；AOE 目标只实现了圆形。

## 三、点击与寻敌边界

点击处理固定遵循以下顺序：

1. 未学习（`level<=0`）不释放。
2. 服务端 `13017` 下发的 `RoleModel.DepositState` 为真时提示“自动战斗中”并拦截。
3. 普通 `AutoFightModel.AutoFightState` 不拦截玩家手点。
4. CD 未结束时由遮罩语义静默拦截。
5. 其余情况发送 `EVT_SKILL_SHORTCUT_CLICK`，由 `SkillController` 进入真实释放链。

手动与自动入口必须分开：

| 入口 | 已有锁定目标 | 无锁定目标 |
|---|---|---|
| 玩家手点 | 按接敌距离判断，范围内释放、范围外接近 | 原地按当前朝向释放；仅允许在技能 `area` 内局部预选 |
| 自动战斗 | 同左 | 可从全场找最近可攻击怪并接近 |
| `obj==1` 自身技能 | 不依赖怪物目标，原地释放 | 同左 |

禁止为了“保证技能打到怪”让手动入口回落到全场最近怪。这会把玩家点按变成一次不可预期的自动寻路。

## 四、配置字段的真实语义

范围判断以 `Assets/GameRes/resource/config/server/config_skill.json` 为准：

| 字段 | 语义 |
|---|---|
| `mod` | `1` 为单体；其他值或缺省为 AOE |
| `obj` | 选取类型：`1` 自身、`2` 最近敌方、`3` 最近队友 |
| `att_obj` | 攻击参照：`1` 自身、`2` 选取对象 |
| `range` | AOE 几何：`1` 圆形、`2` 直线、`3` 扇形；`0` 走圆形缺省，其他未识别值按老端回落圆形 |
| `distance` | 前向距离或几何长度；缺失/0 按老端回落为 50px |
| `area` | 圆形半径、直线总宽度或扇形总角度（度），含义随 `range` 变化 |
| `num[1]` | 最多命中的怪物数量；0 按老端视为 99 |

### 4.1 接敌距离不是命中几何

角色何时停止接近并开始放技能，使用：

```text
range == 1: max(100, (distance + area) * 0.8)
其他模式:   max(100, distance * 0.8)
```

真实配置样例：

| 技能 | 配置 | 接敌距离 |
|---|---|---:|
| `59100001` 御剑一式 | `range=1,distance=100,area=350` | 360px |
| `59100019` 追魂一剑 | `range=1,distance=0→50,area=500` | 440px |
| `59810001` 月华流辉 | `range=2,distance=600,area=300` | 480px |

Unity 修复前御剑一式只有 100px，角色会多贴近 260px，这正是“技能像乱放”的主要来源之一。

### 4.2 命中几何

- 圆形（`range=1`）：有主目标时以目标为圆心；无目标或攻击参照为自身时，以施法者前方
  `GameMath.ChangeEllipseValue(direction,distance)` 为圆心（横向保持、纵向压到 0.5、斜向连续插值）；
  `area` 为半径。
- 直线（`range=2`）：以施法者为起点、当前攻击方向为正向，长度为 `distance`、总宽度为 `area`。
- 扇形（`range=3`）：以施法者为起点、当前攻击方向为中线，长度为 `distance`、总角度为 `area` 度。
- 直线和扇形都保留老端 100px 近身豁免：目标距施法者不超过 100px 时，不再检查方向、长度或夹角。
- 候选按距离稳定升序，已锁定主目标强制放在第一位，再按 `num[1]` 截断。

当前只复刻 PvE 怪物列表；`20001` 的玩家目标列表、伙伴和 PvP `FindRoles` 不在本轮范围内。

## 五、描述文本不是几何权威

当前配置存在文案与结构字段不一致的真实样本。例如 `59100010` 的 `desc` 写“直线范围”，但结构字段为 `range=1`。老端战斗代码读取的是 `range`，不是解析 `desc`。

因此：

- 运行时几何必须服从 `range/distance/area/num`。
- `desc` 只用于显示，不能据此改战斗形状。
- 如果策划认为文案或结构字段有误，应修配置事实源并做双端确认，不能让 Unity 单端“按字面纠正”。

## 六、实现位置与快速排查

关键代码：

- `Assets/Scripts/Module/Core/MainUI/Views/MainUISkillItem.cs`：点击门闩。
- `Assets/Scripts/Module/Core/Skill/SkillController.cs`：手动、自身技能分流。
- `Assets/Scripts/Module/Core/Scene/SceneCombat.cs`：接敌距离、手动/自动寻敌、目标几何和 `20001` 计划。
- `Assets/Scripts/Module/Core/Scene/MainRoleAgent.cs`：当前朝向转换为舞台像素方向。
- `Assets/Scripts/Module/Core/Skill/SkillConfigs.cs`：范围字段读取。

排查顺序：

1. 确认技能是否已学、是否处于 CD。
2. 区分 `DepositState` 与普通 `AutoFightState`。
3. 打印技能的 `mod/range/distance/area/num/obj/att_obj`，不要先看描述猜形状。
4. 区分“接敌距离”与“命中几何”，两者不是同一个半径。
5. 检查调用是否误把手动入口当自动入口。
6. 最后再查 Prefab Raycast、Bind 和遮罩是否挡点。
