# 背包装备仓库交互闭环

> 状态：背包/仓库基础链已完成；共享物品格根组件与流光归属已修。2026-08-08 人工截图推翻了品质流光的旧视觉结论，实例裁切与宿主居中修复已落地，等待新的运行态复验
>
> 最后核对：2026-08-08
>
> 适用范围：`BagModule` 的背包、仓库、物品详情、装备详情、一键装备、装备吞噬、一键使用与容量扩充

## 一、问题与根因

背包和仓库 Prefab 已存在，但多数按钮只有转换后的图片节点，没有业务回调；仓库也没有独立的 `pos=5` 模型。物品格点击未统一进入详情窗，已穿戴格与背包装备没有区分上下文，导致穿戴、使用、对比、存取和右侧按钮看起来全部“无反应”。

本轮以老 Laya 客户端、服务端 handler/writer 和 Unity 当前协议实现三方核对，不以按钮文字猜协议。最终协议边界如下：

| 功能 | 协议与口径 | Unity 行为 |
|---|---|---|
| 容器全量/增量 | `15010/15017/15018`，背包 `pos=4`、仓库 `pos=5`、已穿戴 `pos=1` | 三个容器独立保存；仓库发 `EVT_WAREHOUSE_UPDATE` |
| 穿戴/换装 | `15201(goods_id:u64)` | 只对背包装备显示“穿戴/替换”；成功后重查 `15010 pos=1`，旧装备由服务端换回背包 |
| 普通装备卸下 | `15202` | 不接。老端没有可达 sender，禁止从覆盖率或按钮文案伪造卸下事务 |
| 普通物品使用 | `15050(goods_id:u64,num:u32)` | 只对老端确实走通用使用的物品开放；单个直接使用，堆叠物进入现有 `GoodsFuncView + WithBtnHSlider` 后按当前背包数量二次夹紧 |
| 物品详情 | `15000` 动态详情补充 | 基础资料取 `config_goods/config_equip_attr`，实例洗炼/宝石/附魔按 15000 追加 |
| 仓库存取 | `15003(goods_id:u64,from_pos:u16,to_pos:u16)` | 单击延时打开详情；300ms 内同物双击直接在 4/5 间移动；详情窗也提供存入/取出 |
| 扩容 | `15002(pos:u16,cell_num:u16)` | 背包传 4，仓库传 5；每格消耗 2 个 `38250026`，不足时走服务端自动购买确认 |
| 装备吞噬 | `15024/15025` | 加载真实熔炼配置，最多 50 项，默认只安全选择精华或低评分、低品质、0/1 星候选；自动吞噬设置沿用 `10203 type=4,subtype=1` |
| 一键使用 | 多条 `15050` | 只选 `config_goods.use_one_key!=0` 且满足等级的物品，按礼包/经验书/其他分类选择 |

## 二、界面与数据流

### 2.1 详情和装备对比

详情视觉只复用 `Assets/Prefabs/UI/Common/CommonModule.prefab`。Prefab 中固定保存普通物品板、单装备板、当前装备对比板、候选装备对比板，以及普通半透明遮罩和对比透明遮罩；`ItemTipsView` 只负责数据、显隐、按钮语义和协议，不在运行时创建或定位页面专用视觉树。

`CommonModule.prefab` 是包含多个同级 `BaseView` 的合并模块。独立复用详情时，只关闭最外层同级窗口，再激活目标 Tooltip；嵌套在详情板内的 `EquipmentItem` 等展示组件必须随父窗口保留，不能被“关闭全部 BaseView”误伤。详情关闭时同时失活整个 `CommonModule(ItemTips)` 根，避免关闭态 `ItemUseView` 的烤制数据泄漏到主界面。

层级关系严格对标老端：普通详情打开全屏半透明遮罩；装备对比打开全屏透明拦截层，当前装备板位于 `(-125,+80)`，候选装备板位于 `(+150,-105)`。遮罩与两个板都在背包之上，因此背包关闭按钮不能越过详情被点击；点任一详情关闭按钮或遮罩，统一先关闭整组详情。禁止把详情挂成背包可穿透子层，或在对比状态只显示一个合并面板。

背包装备按 `config_goods.equip_type` 查找 `pos=1` 的同部位装备。槽位为空时显示单板“穿戴”；已有装备时显示两份独立详情，左板只显示“关闭”，右板只显示“穿戴”；已穿戴装备详情只显示“关闭”，仓库上下文只显示“存入”或“取出”。

装备内容顺序固定为极品属性、基础/强化属性、专有属性、宝石属性、洗炼属性。名称、评分、等级、转生职业、部位、品质标题图和属性颜色均按老端配置口径；宝石固定六孔，空孔分别展示未镶嵌、5/7/9/11 阶解锁和 VIP4 解锁，已镶嵌孔展示宝石品质名、图标及 `config_equip_stone_lv` 的两列属性。空孔使用半高行；详情内容超高时仅在面板内部滚动并裁剪，不能覆盖标题、职业栏或伸出面板。

### 2.2 仓库双栏

老端 `WarehouseView.ts` 的命名容易误判，固定映射为：

- `_Scroller1 = ware_scroll`：仓库 `pos=5`。
- `_Scroller2 = goods_scroll`：背包 `pos=4`。
- `expandBtn1` 扩仓库，`expandBtn2` 扩背包。

不要按字段编号或画面上下顺序重新猜映射。全量包保留服务端 `cell`；单击详情与双击存取共享同一物品实例，但用点击令牌取消双击后的延时详情，避免一次双击又弹窗又移动。

### 2.3 Activity 子窗层级

老端 `BagSmeltView`、`OneKeyUseView`、`ExpandBagView` 均使用 Activity 层，并开启 `use_background/click_bg_toClose`。Unity 的等价关系固定为：背包主体位于 `UILayer.Window`，三类子窗位于 `UILayer.Popup`；打开时把承载子窗的 `BagModule` 根提升到 Popup，不能只在背包内部调用 `SetAsLastSibling`。

共享暗幕 `BagActivityBlocker` 直接保存在 `BagModule.prefab`，使用老端 `common/texture/com_sub_bg_7`，并由 `BagActivityModalLayout` 管理。暗幕必须位于当前子窗正下方、拦截整个背包，点击后只关闭当前子窗；子窗关闭后暗幕同步隐藏。吞噬、扩容或一键使用打开时，背包关闭按钮与其余底层操作都不得越过暗幕被点击。

### 2.4 ItemUse 与一键装备

老端一键装备只由玩家点击触发；Unity 不得监听 `EVT_BAG_UPDATE` 自动发送 `15201`，登录也只请求 `15010 pos=1` 作为比较快照。登录时背包 `pos=4` 可能早于已穿戴 `pos=1` 返回，因此装备候选先暂存，必须等 `HasEquipmentData=true` 后按同部位比较；只有候选 `rating` 严格大于当前装备才显示推荐，等分和更低分都不显示。

`ItemUseView` 不是所有非装备物品的通用入口。仅 `config_goods.use!=0` 且老端确实直接走 `15050` 的物品进入“使用”候选；藏宝图、时装、选择礼包、称号、外观、影装等有专属页面或协议的类型，在对应闭环迁移前必须排除，不能展示一个点击后必然失败的通用使用按钮。

### 2.5 点击面

复合按钮根和物品格 `click_group` 是唯一 `raycastTarget`；图标、底板、文字、选中框和数量全部关闭射线。验收必须由真实 Prefab 的 `GraphicRaycaster→PointerClick` 进入生产回调，直接调用业务方法不算通过。

### 2.6 共享物品格与共鸣流光

`EquipmentItem.prefab` 和 `BaseAwardItem.prefab` 的根业务组件是共享 Prefab 身份的一部分，不能为了某个页面的局部视觉修改而删除。背包装备位运行时通过 `BagEquipmentIcon → GetComponent<EquipmentItem>()`，普通格通过 `BagItemRenderer → GetComponent<BaseAwardItem>()` 取得组件；任一根组件缺失都会让多个页面一起退化为空格或静态底板。

套装/共鸣流光是 `EquipmentItem` 提供的槽位能力，不是所有物品格的默认外观。`SetData` 必须先恢复 off；只有 `BagEquipmentIcon` 在持有明确装备部位、传入实例正是 `pos=1` 当前已穿戴实例，并且对应共鸣阶级已满足时调用 `SetSuitEffect`。共鸣状态更新后只重绑已穿戴装备位；普通背包格、仓库格、奖励、材料和详情不订阅也不拥有该特效。共享格随父页面失活、数据重绑或销毁时必须释放异步 Handle，避免关闭页面后仍占用或重开累积。

物品自身的品质流光与套装/共鸣流光是两套独立状态。`config_goods.effect_id` 固定映射 `1004..1009 → ui_goods_orange/ui_goods_red/ui_goods_gold/ui_goods_pink/UI_1309/UI_1310`，由 `BaseAwardItem.effect_con` 或 `EquipmentItem.effect_con` 自动消费；页面不得把它补成页面背景或中央展示特效。`EquipmentItem` 的 `effBox/effBox1/effBox2` 只承载明确 opt-in 的套装流光，两类 Handle 在重绑、失活和销毁时分别释放，不能互相清除或把所有普通物品格都点亮。父页面失活时只释放渲染 Handle、保留当前期望状态；同一数据重开后必须重新挂载，数据重绑/显式清空/销毁才清除期望状态，避免首次可见而关闭重开后流光丢失。

2026-08-08 的玩家运行截图证明，品质动画虽然已创建，但 `BaseAwardItem.effect_con` 仍是左上角 0×0 宿主，且六种资源在共享全屏 RenderTexture 中没有恢复老端每格私有 RT 的裁切，于是动画折线以巨大静态框般的形态散落整页。修复必须保留老端 `scale=14` 和原动画，把 BaseAward 宿主改为围绕 130×130 底板居中的 140×140 矩形，并给六个精确资源 profile 开启 `clipToRenderRect`；`EquipmentItem` 继续使用自身按老端边距伸展的宿主。调用方不得再传脱离宿主的固定 `renderSize`，更不得在背包页补一张静态框。

第二轮截图显示位置虽已正确，但框仍静止且滚出背包 `Viewport` 后留在底栏。根因分别是品质动画写 `_BaseMap_ST`、27 个材质却仍读取 `_MainTex_ST`，以及页面根共享 `RawImage` 不继承列表祖先遮罩。当前修复只在六个品质资源闭包启用 `_UseBaseMapST`，并由 `UIEffectStage` 把实例边界与祖先 `RectMask2D/Mask` 求交；完全滚出时隐藏该 wrapper。以后背包品质流光必须看 2 个以上时间点的真实像素差，并把底部完整、部分裁切、完全不可见三态一起验收，不能用单张位置截图或 `Animation.isPlaying` 代替。

2026-08-08 用户最终运行确认上述两项已恢复：流光为持续动效，底部滚出后没有孤立框。该确认作为背包高频代表消费者的人工运行态结果保存；普通/装备详情及其他宿主仍按各自状态矩阵收口，不能由这一条代表样本代验。

共享槽每次 `SetData` 都必须先清旧状态，再按配置/实例重新呈现。`BaseAwardItem` 负责品质底板、图标、数量、绑定锁、配置限时和物品品质流光；`EquipmentItem` 在此基础上负责装备阶数、四星、劣质标及调用方传入的强化/实例品质；`BagItemRenderer` 负责背包语义的实例限时、穿戴条件禁用，以及与 `pos=1` 同部位装备按 `rating` 严格比较后的升/降箭头。禁止在列表页填完数据后统一 `HideOverlays()`，这会把共享槽已经恢复的真实状态再次抹掉。

修改这两个共享 Prefab/View 时，先静态列出全部直接消费者，再按直接/嵌套、空/有数据、展示/交互、特效开/关和宿主缩放分组。运行态默认抽查目标页、`BagEquipmentIcon` 已穿戴槽与 `BagItemRenderer` 普通格三个代表；样本失败才扩大同组范围，不要求把所有引用页面逐一打开。

### 2.7 普通物品与装备详情布局

普通详情的“物品描述”和“获取途径”不是同一字段：`config_goods.getway`（key `3`）进入详情滚动区的描述段；`getway_url`（key `4`，Erlang `[{open_fun_id,arg},...]`）按原顺序查客户端 `GoodsSourceConfig`，显示在按钮上方的独立来源组。配置资产地址固定为 `resource/config/client/goodssourceconfig`。尚未迁移的功能跳转只显示真实来源名，不得伪造可点击成功。

`GoodsTooltips` 必须按 TMP `preferred height` 动态计算介绍、描述和来源文字；详情区、来源区、按钮区分别排布，面板高度限制在老端的 `450..680`，内容过长时仅滚动详情区。背景必须包围全部可见组，来源底边不得压住按钮顶边，单/双按钮继续由共享按钮容器整体居中。隐藏空文案时必须同时退出布局，不能保留固定 55px 空块或让按钮因空节点向左偏移。

装备详情继续复用 `EquipmentItem`，实例 `color/stren/bind/expire_time` 覆盖静态默认值，阶、星和劣质标走同一共享 setter；普通装备的阶数文字不启用专用 `_img_grade_bg`。详情正文维持“极品→基础/强化→专有→宝石→洗炼”的内容滚动，标题、图标和底部操作区不随正文挤压或拉伸。

## 四、明确边界与 blocker

1. `15202` 普通装备卸下继续保持 `old_client_unreachable`，只允许 `15201` 换装时由服务端退回旧装备。
2. `15218` 仍是会真实扣料、写神装等级并重算属性的 hard-negative；`15221/15222` 已随可编辑 `SuitModule.prefab`、三张同源配置、材料/装备指纹冻结、二次确认、单飞、错误/超时、主动推送及权威重拉整链落地，不再属于 hard-negative。但真实账号最终确认仍会改变装备、背包、货币、邮件或属性，未获具体消耗授权时保持 `blocked`，禁止把确认前取消链或注入回包写成真实成功。
3. 需要专属页面的选择礼包、经验符比较、藏宝图等物品继续走各自迁移边界，禁止为了让通用“使用”按钮有响应而错误直发 `15050`。

## 五、验证

`BagInteractionCase` 同时覆盖：

- `15002/15003/15024/15025/15050/15201` 的命令号、字段顺序、宽度和大端字节。
- 真实 `BagModule.prefab` 的一键装备、吞噬、扩容、一键使用，以及仓库对应按钮的唯一点击面和 `GraphicRaycaster→PointerClick`。
- 真实 `CommonModule.prefab` 详情窗的正文、双独立装备对比、标题图标、属性分类、六个宝石孔、使用、穿戴、存入和取出点击。
- 详情专用 CommonModule 只激活目标最外层 Tooltip，确认同级 `ItemUseView` 不会泄漏、嵌套装备图标不会被误关；详情关闭后模块根必须整体失活。
- 从真实 `GraphicRaycaster` 点击面板外角，必须先命中详情遮罩、关闭详情且底层背包关闭按钮计数仍为 0。
- 吞噬、扩容和一键使用打开后必须位于 Popup；真实 Raycaster 点击 `BagActivityBlocker` 时先关闭子窗且不触发背包按钮。
- ItemUse 路由必须验证：普通通用品点击发送精确 `15050`，藏宝图和时装不进入通用候选；装备在穿戴快照未到时不推荐，只接受严格高分；一键装备不存在背包更新自动入口。
- 人物页共鸣按钮必须进入当前 `SuitModule.prefab`；共鸣材料点击继续复用同一个 `CommonModule.prefab/GoodsTooltips`，类型/数量栏和单/双按钮居中状态需要随共享详情回归，禁止页面内复制第二套详情坐标。
- 共享格回归必须先确认 `EquipmentItem`/`BaseAwardItem` 根组件和嵌套模板引用仍存在，再分别抽查背包装备位有数据/空槽、共鸣状态开/关、普通背包格显示和关闭重开清理；普通格出现流光、装备位取不到组件或一个页面修好后另一个页面变灰都算失败。
