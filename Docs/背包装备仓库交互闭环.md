# 背包装备仓库交互闭环

> 状态：基础链已完成；套装共鸣模块受老端运行快照阻塞
>
> 最后核对：2026-07-31
>
> 适用范围：`BagModule` 的背包、仓库、物品详情、装备详情、一键装备、装备吞噬、一键使用与容量扩充

## 一、问题与根因

背包和仓库 Prefab 已存在，但多数按钮只有转换后的图片节点，没有业务回调；仓库也没有独立的 `pos=5` 模型。物品格点击未统一进入详情窗，已穿戴格与背包装备没有区分上下文，导致穿戴、使用、对比、存取和右侧按钮看起来全部“无反应”。

本轮以老 Laya 客户端、服务端 handler/writer 和 Unity 当前协议实现三方核对，不以按钮文字猜协议。最终协议边界如下：

| 功能 | 协议与口径 | Unity 行为 |
|---|---|---|
| 容器全量/增量 | `15010/15017/15018`，背包 `pos=4`、仓库 `pos=5`、已穿戴 `pos=1` | 三个容器独立保存；仓库发 `EVT_WAREHOUSE_UPDATE` |
| 穿戴/换装 | `15201(goods_id:u64)` | 只对背包装备显示“穿戴/替换”；成功后重查 `15010 pos=1`，旧装备由服务端换回背包 |
| 普通装备卸下 | `15202` | 不接。老端没有可达 sender，禁止从覆盖率或按钮文案伪造卸下事务 |
| 普通物品使用 | `15050(goods_id:u64,num:u32)` | 单个直接使用；堆叠物进入现有 `GoodsFuncView + WithBtnHSlider` 后按当前背包数量二次夹紧 |
| 物品详情 | `15000` 动态详情补充 | 基础资料取 `config_goods/config_equip_attr`，实例洗炼/宝石/附魔按 15000 追加 |
| 仓库存取 | `15003(goods_id:u64,from_pos:u16,to_pos:u16)` | 单击延时打开详情；300ms 内同物双击直接在 4/5 间移动；详情窗也提供存入/取出 |
| 扩容 | `15002(pos:u16,cell_num:u16)` | 背包传 4，仓库传 5；每格消耗 2 个 `38250026`，不足时走服务端自动购买确认 |
| 装备吞噬 | `15024/15025` | 加载真实熔炼配置，最多 50 项，默认只安全选择精华或低评分、低品质、0/1 星候选；自动吞噬设置沿用 `10203 type=4,subtype=1` |
| 一键使用 | 多条 `15050` | 只选 `config_goods.use_one_key!=0` 且满足等级的物品，按礼包/经验书/其他分类选择 |

## 二、界面与数据流

### 2.1 详情和装备对比

详情视觉只复用 `Assets/Prefabs/UI/Common/CommonModule.prefab`。Prefab 中固定保存普通物品板、单装备板、当前装备对比板、候选装备对比板，以及普通半透明遮罩和对比透明遮罩；`ItemTipsView` 只负责数据、显隐、按钮语义和协议，不在运行时创建或定位页面专用视觉树。

`CommonModule.prefab` 是包含多个同级 `BaseView` 的合并模块。独立复用详情时，只关闭最外层同级窗口，再激活目标 Tooltip；嵌套在详情板内的 `EquipmentItem` 等展示组件必须随父窗口保留，不能被“关闭全部 BaseView”误伤。详情关闭时同时失活整个 `CommonModule(ItemTips)` 根，避免关闭态 `ItemUseView` 的烤制数据泄漏到主界面。

层级关系严格对标老端：普通详情打开全屏半透明遮罩；装备对比打开全屏透明拦截层，当前装备板位于 `(-125,+80)`，候选装备板位于 `(+150,-105)`。遮罩与两个板都在背包之上，因此背包关闭按钮不能越过详情被点击；点任一详情关闭按钮或遮罩，统一先关闭整组详情。禁止把详情挂成背包可穿透子层，或在对比状态只显示一个合并面板。

背包装备按 `config_goods.equip_type` 查找 `pos=1` 的同部位装备。槽位为空时显示单板“穿戴”；已有装备时显示两份独立详情，左板只显示“关闭”，右板只显示“穿戴”；已穿戴装备详情只显示“关闭”，仓库上下文只显示“存入”或“取出”。

装备内容顺序固定为极品属性、基础/强化属性、专有属性、宝石属性、洗炼属性。名称、评分、等级、转生职业、部位、品质标题图和属性颜色均按老端配置口径；宝石固定六孔，空孔分别展示未镶嵌、5/7/9/11 阶解锁和 VIP4 解锁，已镶嵌孔展示宝石品质名、图标及 `config_equip_stone_lv` 的两列属性。空孔使用半高行；详情内容超高时仅在面板内部滚动并裁剪，不能覆盖标题、职业栏或伸出面板。

### 2.2 仓库双栏

老端 `WarehouseView.ts` 的命名容易误判，固定映射为：

- `_Scroller1 = ware_scroll`：仓库 `pos=5`。
- `_Scroller2 = goods_scroll`：背包 `pos=4`。
- `expandBtn1` 扩仓库，`expandBtn2` 扩背包。

不要按字段编号或画面上下顺序重新猜映射。全量包保留服务端 `cell`；单击详情与双击存取共享同一物品实例，但用点击令牌取消双击后的延时详情，避免一次双击又弹窗又移动。

### 2.3 点击面

复合按钮根和物品格 `click_group` 是唯一 `raycastTarget`；图标、底板、文字、选中框和数量全部关闭射线。验收必须由真实 Prefab 的 `GraphicRaycaster→PointerClick` 进入生产回调，直接调用业务方法不算通过。

## 四、明确边界与 blocker

1. `15202` 普通装备卸下继续保持 `old_client_unreachable`，只允许 `15201` 换装时由服务端退回旧装备。
2. `15218/15221/15222` 是会改变装备、背包或货币的真实套装事务，不能先接一个按钮、裸 sender 或成功 Toast。当前仓库没有 `EquipSuitBaseView` 可编辑 Prefab，且老端 `127.0.0.1:8090` 快照服务不可达；按转换流水线，必须先取得运行时 snapshot/manifest，再完成整页 Prefab、配置、预校验、单飞、结果与资产刷新闭环。因此“共鸣打造”暂时关闭射线，不伪装完成。
3. 需要专属页面的选择礼包、经验符比较、藏宝图等物品继续走各自迁移边界，禁止为了让通用“使用”按钮有响应而错误直发 `15050`。

## 五、验证

`BagInteractionCase` 同时覆盖：

- `15002/15003/15024/15025/15050/15201` 的命令号、字段顺序、宽度和大端字节。
- 真实 `BagModule.prefab` 的一键装备、吞噬、扩容、一键使用，以及仓库对应按钮的唯一点击面和 `GraphicRaycaster→PointerClick`。
- 真实 `CommonModule.prefab` 详情窗的正文、双独立装备对比、标题图标、属性分类、六个宝石孔、使用、穿戴、存入和取出点击。
- 详情专用 CommonModule 只激活目标最外层 Tooltip，确认同级 `ItemUseView` 不会泄漏、嵌套装备图标不会被误关；详情关闭后模块根必须整体失活。
- 从真实 `GraphicRaycaster` 点击面板外角，必须先命中详情遮罩、关闭详情且底层背包关闭按钮计数仍为 0。
- 共鸣按钮在完整模块缺失时不保留错误的射线命中面。

`PetEquipInventoryCase` 追加 `pos=5` 的 `15010/15017/15018` 全量、更新、删除、数量变化、事件次数和与主背包隔离；`GoodsProtoCase` 保留既有 15000/15002 等协议回归。

2026-07-31 回归结果：`BagInteractionCase=0`，日志为 `isolated=True/closeRoot=True/compare=True/icons=True/configGroups=True/blocker=True/pass=True`；Unity 强制编译 `completed/failed=false/errors=[]`。既有 `PetEquipInventoryCase=0`、`GoodsProtoCase=0` 结论不变。
