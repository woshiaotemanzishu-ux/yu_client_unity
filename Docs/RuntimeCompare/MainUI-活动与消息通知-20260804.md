- Unity 截图中，左上活动网格多出 `61207`“圣衣秘境”；老 Web 客户端同账号同一时段不显示该入口。
- 中部通知条逐图标核对后，Unity 为“首杀 / 资源找回 / 等级奖励”三项；老端为“首杀 / 邮件 / 资源找回 / 等级奖励”四项。缺失项是邮件 `ui_notice_3`。
- 老端 `MainUISecondaryView.PlayNotificationAnimation` 让全部有效通知同相摆动：首段 `0→+20°`，之后每 1000ms 在 `+20°/-20°` 间按 sine-in-out 往返。Unity 原通知条只有动态布局和点击，没有这段动画。

原始截图已保存到 `output/ui_route_audit/2026-08-04_mainui_notifications/`，避免继续引用会被系统清理的剪贴板临时路径。

## 根因与修复

### 1. `612xx` 错入活动网格

老端在活动排版末尾执行 `Suppress612ShopActivityIconsForChatBar`，所有 `icon_type` 以 `612` 开头的限购商城入口都退出活动网格，只保留底部商城入口/特效语义。Unity 分组槽位重构后的 `MainUIActivityView.CollectOwnedIconGroups` 直接按 `location_type` 收集，漏掉了这条专门分流，因此服务端下发的 `61207` 被当成普通 loc2 活动展示。

修复在当前 `MainUIActivityView` 增加序数前缀过滤；只排除 `612`、`61207` 等 `612xx`，不会误伤 `621/62107`。没有重转或改写 `HudActivity.prefab`。

### 2. 邮件通知首屏缺失

邮件 `19001/19008` handler 和 `MailModel.HasUnread` 已存在，但 Unity 进游戏链没有发起邮件启动查询；只有打开邮件页时才请求 `19001`。主界面通知条读取默认 `HasUnread=false`，因此 `ui_notice_3` 永远少一项。

老端 `FriendController` 在 `GAME_START` 固定先发 `19008`、再发 `19001`。Unity 现在在 `MailController` 的 `EVT_GAME_START` 订阅中恢复同一顺序，`19008` 回包仍是未读状态的唯一权威来源，并通过既有 `EVT_MAIL_UNREAD_UPDATE` 即时刷新主界面；没有用邮件列表或本地猜测覆盖服务端状态。

### 3. 通知条无摇摆

动画属于运行态状态表现，继续由 `MainUINotificationView` 管理，不把 Tween 或状态写进 Prefab。View 使用 `Time.unscaledDeltaTime` 统一计算角度并同时赋给所有可见 `MainUINotificationItem`，保证同相；通知从无到有时从 0° 起步，隐藏、复用或关闭 View 时恢复单位旋转，避免旧角度残留。
