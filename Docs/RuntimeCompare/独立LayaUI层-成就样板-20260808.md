# 独立 Laya UI 层：成就样板（2026-08-08）

> 2026-08-09 落地纠偏：当前 Unity 工程没有 Editor/Android 可用的 WebView/Chromium 宿主，下面的结果只证明“浏览器宿主页同时承载 Unity WebGL 与旧 Laya”的架构样板可行。它不会出现在用户直接运行的 Unity Editor/原生客户端中，不能作为当前成就页的交付方案；现阶段继续在既有 UGUI Prefab 上增量修复并做真实运行态验收。

## 结论

WebGL 路线可行：Unity WebGL 保持运行在下层，旧 Laya 成就页作为独立浏览器层覆盖在上层。成就页不是截图，也没有转换成 UGUI/FairyGUI，而是直接运行旧端真实 `AchvEnterView`；因此在同一 viewport、资源和配置下，成就页视觉就是旧端自身，不再依赖人工逐节点还原。

本轮样板已通过“直接打开 → 真实页签点击 → 关闭 → 热重开 → 再关闭”。关闭时整层同时切换为 `opacity=0 / visibility=hidden / pointer-events=none`，命中目标恢复为 `unity-frame`；第二次关闭后的截图已回到 Unity 真实登录页，没有出现成就奖励图标或其他 Laya 残留。

这证明的是“独立层复用旧 UI”的可行性，不代表当前 UGUI 成就路线已经验收，也不等于生产数据桥、原生 Android/iOS 支持已经完成。

## 样板结构

- 宿主页同时承载 `unity-frame` 与 `laya-frame`，Unity 在下、Laya 在上。
- Laya 登录和预热阶段不可见；宿主通过桥直接触发 `achvModel.OP_V → AchvEnterView`，不再绕旧端主界面固定坐标。
- 运行时检测成就 `tabScroller` 的真实显隐，并通过 `postMessage` 发送 `achievement-open/close`。
- 打开事件原子赋予 Laya 可见性与输入；关闭事件原子隐藏整个 Laya frame，并把输入归还 Unity。
- 每次打开重新解析当前 `BaseWindowSkin` 实例。旧端 `destroy_imm=true` 会在重开时创建新实例，禁止复用旧节点身份。

可重跑脚本：`Tools/RuntimeUiLayer/achievement_layer_poc.cjs`。

## 当前边界

1. 当前是“独立层 + 完整旧 Laya 运行时”，不是已经裁成只含成就的独立包。首次准备约 53 秒，页面自身只需 37～180 ms；生产版必须拆开“运行时预热成本”和“页面打开成本”。
2. 旧 Laya 本轮使用已记录的 `123123` 测试号独立登录；Unity 没有登录同一账号。生产版不能让两端各自拥有账号会话，否则会出现踢号、状态竞争和双协议源。
3. 下一道决定性门槛是让 Unity 成为唯一账号/网络权威：Unity 把成就快照和增量交给 Laya，Laya 点击把 `40902/40905` 意图回传 Unity，由 Unity 正式协议发送并把权威结果再推回 Laya。
4. 当前页面覆盖的是完整旧端画面，因此能直接得到旧端视觉；若只保留成就模块、隐藏旧主界面和场景层，必须重新验证裁切、层级、声音、特效、返回链和资源闭包。
5. 本轮只验证浏览器/WebGL 双层。Android/iOS 若采用 WebView 或嵌入式 Laya runtime，需要另做内存、包体、输入、生命周期和平台合规样板，不能由本报告代替。

## 对现有成就路线的影响

当前 UGUI 成就仍维持 `implemented-needs-runtime + write-blocked`，schema 6 v2 台账不因本样板自动变绿。若后续选择 Laya 独立层作为正式架构，应新建一条“Laya 层成就”路线，验收数据桥、唯一协议权威、资源/内存、双 viewport、关闭清理和原生平台；不应把这次可行性证据混入 UGUI Prefab 的完成状态。
