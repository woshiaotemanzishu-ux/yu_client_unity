# 角色-垂神翼影运行态通用转换实验（2026-08-12）

## 结论

本轮结论为 **Conditional Go**：老客户端真实运行树可以重新驱动现有通用转换核心，并在隔离目录快速生成一个肉眼可辨、图片资源完整、绝大多数静态几何直接可用的 UGUI 候选；但当前快照没有捕获文字值，也没有包含独立合成的 3D 翅膀、动态特效、运行时材质/滤镜和完整克隆语义，因此不能把候选注册为生产 Prefab，更不能据此宣称“垂神翼影”页面完成。

首个候选满足 15～30 分钟目标：从首份权威目标快照到候选 PNG 为 **7 分 04 秒**。从整个实验开始算，因先把重复的 ItemUse、共享窗框 wait-view、Canvas 身份点击和协议白名单问题晋升为公共工具，首份权威目标快照出现在 **39 分 58 秒**，首候选在 **47 分 02 秒**，首个有效 diff 在 **49 分 27 秒**。工具编译完成后，用输出文件作为 ready 探针的热重跑实测 **529 ms** 到 render report 就绪；这个数字只代表“既有快照 → 已编译转换器 → 隔离候选出帧”，不包含登录、导航、状态采集或人工验收。

实验没有修改或重转 `PetModule.prefab`、`RoleModule.prefab`，没有调用 `BakeModuleFromManifest`，没有注册 Addressables，没有进入 `fix-view`，也没有修改受保护的“角色-人物”完成范围和既有 `outward-wing*.json`。唯一生成进 `Assets` 的候选位于 `Assets/__RuntimeConversionExperiment/RoleOutwardWing/`。

## 状态与不支持项

UIAudit route 能表达并复现“MainUI → 角色过境 → 垂神翼影主态 → 幻化只读态”的点击链、身份条件、前后 snapshot 和精确读协议；当前转换候选本身只是一份主态静态 Prefab，不能表达业务点击、状态切换或协议。

当前不能自动恢复：

1. 3D 翅膀模型及其独立 UI/场景合成；该对象不在 managed `OutWardBaseView` 子树中。
2. 粒子/时间轴动态、运行时材质参数、滤镜和两时点像素语义。
3. 列表/模板克隆的实例 provenance 与最终独立平移；这正是 p95 几何尾部的主要来源。
4. 文本内容、富文本/位图字体最终值；类型壳存在，但运行态采集值为空。
5. 共享窗框、底部角色页签和候选子树之外的组合层；本轮没有用生产 `RoleModule.prefab` 冒充候选或答案。

## 工时、可省与不可省

完整 timing 位于同一实验根的 `route-timing.json`。总墙钟 **58 分 51.050 秒**，记录到具体 phase 的 active 为 **46 分 24.951 秒**，独立环境 wait 为 **0**；另有 **12 分 26.099 秒** 是 phase 之间的工具返回、结果阅读和短交接开销，单列为 inter-phase overhead，不冒充环境等待。真实 H5 的登录/动画/ready 等待保留在其运行阶段内，没有改写成“可删除等待”。成功的 run012 总墙钟 39.802 秒、phase 43.431 秒、route steps 8.294 秒，其中配置 settle 仅 300 ms，故固定等待的理论可省上限只有 **300 ms**；runtime ready 1.892 秒和真实登录约 29.909 秒不能直接删。

可以实际省下的时间：

- 热会话复用登录、一次采集主态/状态态、缓存运行树与资源解析，避免每个状态重新启动会话。
- 已编译隔离入口 + 输出 ready 探针：本轮首实现/出帧阶段 380.064 秒，热重跑到 report ready 为 529 ms；可摊销约 379.535 秒的“首次工具实现与编译”成本。
- 多个 Tab 先批量采 snapshot，再进入一次 Unity 串行队列烘焙，避免反复定向编译和菜单往返。
- 图片只复用已导入资源并缓存 skin 解析，不物化缺图、不改 importer、不做全库 Refresh。

不能省：老端当前状态的真实进入与协议硬停、运行树/Canvas 身份门禁、动画和资源 ready、3D/特效两时点像素、状态交易授权、最终真实组合页和 WebGL 验收。也不能把 529 ms 热出帧当成一个生产 Tab 的完工时间。

对“纯 UI 一个 Tab ≤ 1 小时”的目标，本轮静态 2D 候选具有明显余量，但文字、克隆和组合缺口仍需工具补齐后再测人工收口时间。因此本轮不是无条件 Go。

## 下一轮最多三个工具改造

1. 在 normalized runtime tree 中补齐最终 `text/htmlText/font/bitmapFont` 与渲染后文字包围盒，并以当前 12 个缺失 Text 做 fixture。
2. 给重复实例保存稳定 runtime instance key 与最终父内局部矩阵，转换时禁止模板索引重新排布，先关闭 `0/-20/-40 px` 克隆塌缩。
3. 增加 managed 子树之外的组合引用清单，只记录 3D/特效/共享窗框的 ownership 和占位合同；不把它们伪转成静态图片。
