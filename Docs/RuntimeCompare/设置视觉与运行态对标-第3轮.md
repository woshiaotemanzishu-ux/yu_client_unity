## 1. 为什么重开

第 2 轮证明了设置控件能点击、协议能闭环、改名能即时刷新，但用户用老端与 Unity 截图复查后仍发现模型缺失、套装构图偏移、灰显与红点状态错误，以及页内“更换”按钮未被真正点击。由此确认：CLI 通过只证明功能层，不自动证明玩家看到的运行态、视觉和性能。

本轮把完成定义改为四层同时通过：

1. 功能：真实 `GraphicRaycaster→PointerClick`、路由、协议、结果、即时刷新、重开和返回链。
2. 运行态：同状态核对选中、激活、穿戴、锁定、红点、战力、按钮文案与条件显隐。
3. 视觉：720×1280 下 2D 像素级对照；3D 只要求模型存在、部件正确、无镜像/翻转/明显错误角度、位置比例大致正常、常驻特效一致。
4. 性能：首开、热开、350ms/1000ms/ready 检查点、资源闭包幂等和点击后零新增。

## 2. 实际修复

### 2.1 可编辑 Prefab 与 2D 状态

- 继续以 `SettingModule.prefab`、`DressModule.prefab`、`FashionModule.prefab` 为视觉事实源，直接增量修正列表、套装竖牌、战力区、页签、裁剪和布局；没有重转模块或运行时重建页面。
- 未激活时装与套装材料从透明 tint 改为真正的 UGUI 灰阶材质，避免“颜色变淡但并未灰显”。
- 时装/发饰红点改为按下一阶配置和权威背包材料是否充足计算；背包变化时立即重算。未激活、可操作、材料清空三个状态均已回归，禁止把全部未激活项一律标红。
- 发饰默认选中项与当前穿戴项分离：选中框保持老端第一个可操作/首项，`使用中`只标权威穿戴项。

### 2.2 3D 模型与特效

- 时装/发饰复用老角色组合装配，切服装、发饰和三个染色档时即时重建模型；保留武器与骨骼常驻特效。
- 套装四页逐页装配衣服、发饰、坐骑、翅膀和武器；切页先失活旧实例再延迟销毁，防止非 PlayMode 同帧渲染把上一页部件累积到下一页。
- `UIModelStage` 的方向、缩放和落点按截图调整。跨引擎轮廓、抗锯齿和 Shader 不做逐像素强等价，但没有模型缺失、镜像、翻转或明显错误角度。

### 2.3 页内功能与即时状态

- 套装页四个预览页签全部点击；可见“更换”按钮真实打开确认框，按套装条件发送两条 `41302`，权威回包后当前页立即从“更换”切为“已更换”，关闭重开仍保持。
- 迁入 3D 预览时曾误删 `FashionMainView` 的 `41312` 战力刷新。串行旧回归发现 `fightDisplayOk=False` 后恢复 `_box_fight/FightingShowSmallItem` 数据链，最终 `FashionCase` 全绿。
- 设置完整功能树仍覆盖两页签、四滑杆、三拾取、十屏蔽、自动任务、改名、法律文本和底部确认链；串行用例开始前清理上一轮中断残留的 10203 测试队列，避免模拟回包错配造成假失败。

### 2.4 资源与冷启动

- `FashionAssetPreflight` 按模型、染色、消耗、套装部件与特效配置计算 712 项闭包；第二次执行为 `imported=0、configured=0、added=0、missing=0`。
- `DressAssetPreflight` 为 `required=154、added=0、missing=0`；玩家点击前后 `addedResources=none`。
- 头像预览采用版本化异步请求并暴露真实 ready 状态；旧请求不能覆盖新页，资源未到前不显示粉块或旧图残影。

## 4. 当前边界

- 本轮没有构建、发布或部署 WebGL，不把 Editor CLI 与真实账号 Editor 截图描述为“部署后 Web 已通过”。
- 3D 不以像素差图判定轮廓一致；判定口径是模型存在、资源部件正确、无镜像翻转和明显错误角度、位置比例大致正常、常驻特效一致。
- 后续改设置/时装/装扮视觉继续直接编辑当前 Prefab；页面已接管后禁止重转、批量复制整页覆盖或恢复页面专用 Creator 自动重建。
