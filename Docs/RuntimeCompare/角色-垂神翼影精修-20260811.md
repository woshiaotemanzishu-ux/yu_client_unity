## 静态根因与本批实现

确认七类根因：

1. 16002 只返回已解锁技能，Unity 原逻辑据此隐藏未解锁槽，违反老端“全部四槽常驻、仅灰态”的语义。
2. 材料槽绕过 `BaseAwardItem.SetData`，共享组件内部 `_typeId` 保持 0，默认详情点击无效。
3. 属性页与不可用魔晶详情页缺少业务 View/Prefab。
4. 幻化页缺少业务 View/Prefab。
5. 等级线子页缺少业务 View/Prefab。
6. 仙愿入口被固定隐藏，页面仍为 TODO 占位。
7. 基础外观 `illu_group` 没有点击绑定，无法执行老端 16003 基础外观穿戴/恢复语义。

本批已实现：

- 新增 `OutWardConfigs.GetDefaultSkillIds(typeId)`，按 `config_mount_skill type=1/stage` 排序；View 再按 `config_skill.type!=1` 过滤。
- 技能四槽常驻，16002 仅决定解锁/灰态；技能点击复用 `CommonModule/SkillTipsView`。
- 材料槽调用 `BaseAwardItem.SetData`，恢复真实 goodsId 详情身份，并对齐老端 0 隐藏、1 起显示。
- `illu_group` 恢复基础外观点击：当前非基础外观时穿当前 stage；已穿且 stage>1 时恢复 stage 1；stage 1 显示“无法取消当前形象”。
- 技能详情 cold 加载时关页会清空 pending，防止宿主关闭后异步弹窗迟到。
- 定向 `OutWardCase` 增加 type_id=3 的 4 技能/3 材料/3 魔晶配置顺序，以及 type 1/type 4 代表形态的静态断言。

属性、魔晶详情、幻化、等级线、仙愿仍是独立缺失叶；消费型事务仍未授权。本批没有把它们降级成“能开壳即完成”。
