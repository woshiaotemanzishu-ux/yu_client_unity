# UIAudit 公共采集与探针基础设施（2026-08-11）

## 1. 结论与边界

UI 精修的老 H5 采集、登录进城、运行树识别、Canvas 输入、启动弹窗、`ItemUseView` 和协议安全探针已从单条路线脚本产品化到 `Tools/UIAudit/`。正式 CLI 使用项目既有 Puppeteer 依赖驱动系统 Edge 的真实 Headless 页面；截图来自浏览器真实 Canvas，不存在合成假截图。

本轮只完成公共模块、fixture 测试、文档和 Git 跟踪策略。没有启动 Unity、没有构建 Addressables/WebGL、没有登录游戏、没有执行页面验收或账号事务，因此不改变 A/B/C/D 页面精修及其自动化的暂停状态，也不把任何页面升级为 `done`。

## 2. 架构与调用链

```text
route.json（页面只写控件、路线、断言）
  -> cli.cjs preflight
  -> HeadlessUiSession（登录/选角/进城/热会话）
  -> runtime-tree + canvas-input
  -> popup-policy / item-use / protocol-probe
  -> route-runner
  -> output/<route>/<new-run>/（真实截图、snapshot、trace、report）
```

公共 API 与命令见 `Tools/UIAudit/README.md`。版本固定在 `lib/version.cjs`；route、report 和统一节点分别有 v1 schema。`preflight` 检查 Node 22、系统 Edge、`Tools/headless` Puppeteer、JSON 路线、策略、凭证、authority 哈希、输出位置和新目录不可覆盖。`run` 只有 preflight 全绿后才启动浏览器。

运行树同时采集：

1. `__sxListLoadedPages__` 的 loaded view 身份；
2. `__sxExportPageSnapshots__` 的 managed view 树；
3. `Laya.stage` 的真实显示树、世界矩形、pivot/anchor/scale、可见性、命中、滚动和浅层数据身份。

三者统一为 `ui-audit.runtime-node.v1`，节点保留 `source/view/path/indexPath`，避免把嵌套 View 漏判为“未加载”，也避免仅凭同名 managed view 误点另一实例。Canvas click/drag 在真实输入前强制通过唯一实例数量、viewport、display/mouse 状态和目标节点 `hitTestPoint`。

## 3. 安全策略

### 3.1 启动弹窗

`policies/startup-popups.json` 独立保存 16 个已审弹窗的识别节点、安全关闭面、危险节点、open/close 副作用、协议、持久写入、源码路径和 SHA-256。决策只有：

- `allow`：关闭链没有协议或持久写入，且只能点配置中的精确安全节点；
- `forbid`：例如 `ItemUseView`、`PartnerAwakeShowView`、`kfStageShowView`；
- `unknown-hard-stop`：未审 View 不尝试“点右上角”“点中心”或猜 Controller。

队列按 View 名去重、按权威 sort 排序；真实 visible stack 处理时以当前顶层为先。`CongratulationObtainView`、`RuneTreasureResultView` 允许配置最多两次的本地演出完成/关闭，仍不得点击其事务节点。

### 3.2 ItemUseView

通用启动弹窗引擎永远禁止关闭 `ItemUseView`。只有路线显式提供本轮一次性授权、完整预期身份和队列路径时，才可调用 `closeItemUseControlled`：

1. loaded view 与 stage root 都必须恰好一个；
2. 名称、底部提示、按钮文案、close/enter 节点及可用时 typeId 必须一致；
3. 连续两个 Laya 帧均已停止动画、关闭面可命中、frame token 前进且矩形稳定；
4. 保存 ItemUse 队列前后；
5. 关闭前后读取同一 `UserMsgAdapter` trace，required/forbidden 和 read-only 分类全部通过；
6. 关闭只能点击一次，第二实例或误发 `15050/15201/15302` 等写协议立即失败。

### 3.3 协议

协议探针包装 `UserMsgAdapter.SendAllFmtToGame` 与显式声明的 S2C handler，记录真实收发。`policies/protocols.json` 只把来源已核实且签名完全匹配的请求分类为 `system/read`；已证实写协议分类为 `write`；已知号格式/参数不匹配记 `malformed`，未知号记 `unknown`，read-only 路线均硬停。页面路线只传 `required/forbidden/min/max/fmt/args/payloadFields`，不得猜 Controller 调用或用 Model 最终值替代传输证据。

## 8. 后续页面路线硬规则

1. 页面路线只写 JSON 数据：route map、控件 selector、预期 View/状态、协议 required/forbidden 和截图点。
2. 登录、选角、进城、热会话、运行树、JSON、弹窗、ItemUse、协议和报告一律 require/调用 `Tools/UIAudit`。
3. 同一种基础设施缺陷首次出现可在当前页定位；第二次出现立即停止页面实现，登记公共 blocker 并晋升到 `Tools/UIAudit`，补回归后才继续页面。
4. `output/` 只存新 run 的不可变截图、snapshot、trace、报告和索引；公共代码、策略、fixture、schema、路线模板不得放入其中。
