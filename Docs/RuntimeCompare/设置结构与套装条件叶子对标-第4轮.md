# 设置结构与套装条件叶子对标：第 4 轮

> 日期：2026-08-04
>
> 范围：设置 → 更换头像 → 时装/套装；重点处理列表容器、套装竖牌页面坐标、四个条件格详情弹窗与资源冷开
>
> 结论：第 3 轮的“视觉完成”已被用户证据推翻。本轮将目标身份、容器结构、真实拖动和页面坐标升级为机器硬闸；最终运行结果以本页第 4 节为准。未进行 WebGL 构建或部署后复验。

## 1. 用户证据推翻了什么

1. 时装横排虽然能显示 5～6 个条目，但绑定节点不是老端等价的可滚动 Content；没有 Viewport 裁剪，也不能拖到后续项。
2. 套装竖牌的局部 RectTransform 数字看似接近，实际父容器已位于页面 x=599，子图又使用右锚 x=-45，最终页面坐标整体右偏 65px。
3. 套装四个条件格继承 `BaseAwardItem` 默认点击，打开的是通用小物品窗；老端按物品类型进入 `IllusionTips` 大卡。第 3 轮只检查灰阶图标，没有逐格点击，因此未发现。
4. 首次自动修复虽然改成了 `IllusionTips`，截图复核又发现品质大底图没有绘制：`IllusionTips.scene` 的 `_img_bg` 本来没有静态 skin，老端会按 `goods.color` 动态加载 `ui_tips_pzbg_1..7`。只断言 View 类型和 426×772 尺寸仍会假绿。

## 2. 根因与修复

### 2.1 唯一真实滚动容器

- `FashionModule.prefab` 原本同时存在一个带 `ScrollRect` 的旧容器和一个被 Bind 指向的重叠横排节点；业务向后者克隆条目，所以截图会越界且不能滑。
- 删除重叠假 Content，把 `_list_fashion_item` 直接绑定到真实 ScrollRect.Content。
- Content 保存 `HorizontalLayoutGroup(spacing=14) + ContentSizeFitter(horizontal=PreferredSize)`；ScrollRect 固定为横向，Viewport 保存 `RectMask2D`。
- 自动用例从 Viewport 内可见条目命中射线，执行 `BeginDrag→Drag→EndDrag`，要求 Content x 位移超过 20px，再复位继续后续点击。

### 2.2 页面坐标而不是局部坐标

- 套装 `_right_box` 的老端页面位置是 `(599,19)`；内部 `Image_130` 应从父左上 `(0,0)` 开始，尺寸 `103×284`。
- 当前 Prefab 直接改为左上锚，不在运行时写位置。
- 用例通过世界角点反算到 `FashionSuitView` 根左上角，断言最终页面矩形 `(599,19,103,284)`；锚点不同但屏幕结果相同可通过，局部数值相同但屏幕偏移会失败。

### 2.3 四个条件格逐叶核查

- `FashionSuitGoodsItem` 覆盖 `BaseAwardItem` 的默认点击，四格分别进入 `IllusionTipsFlow`。
- 复用 `CommonModule.prefab/IllusionTips` 现有可编辑视觉树；运行时代码只填名称、基础属性、来源、战力和模型，不重建 UI。
- 新增 `ConfigIllusionModel` 运行时读取，时装/发饰按职业组合角色，坐骑/羽翼/神兵等按 `model_type/model_res/scale/pos/rotate/action_list` 展示并挂常驻特效。
- 逐格硬闸：实际 View 必须为 `IllusionTipsBind`，不能同时存在 `GoodsTooltipsBind`；根 `450×600`、底图 `426×772`；模型 ready；非角色幻化要求有特效；遮罩外点击可关闭；单次耗时低于 5 秒。

### 2.4 动态品质底图与资源闭包

- `IllusionTipsFlow` 按 `GoodsModel.GetDisplayColor` 加载 `common4/other/ui_tips_pzbg_{1..7}`，视觉 ready 必须同时满足模型纹理与底图 Sprite 非空、Image 启用且未被 Canvas cull。
- `FashionAssetPreflight` 把七张 400KB 级品质底图、`ConfigIllusionModel`、四格物品图标及既有时装资源一起放入点击前闭包和 Addressables。
- 这避免了玩家第一次点击才从老客户端复制 PNG/.meta 的数秒停顿；第二次预检仍必须 `imported=0、configured=0`，点击后资源目录零新增。

### 2.5 实际出帧与动态文案布局

- 首轮大卡虽然已有模型 GameObject、Renderer 和 RenderTexture，截图仍可能空白。根因是 RawImage 一拿到 RT 就把 `IsModelReady` 置真，而专用相机尚未完成第一次 `Render()`。
- `UIModelStage` 现在只在 `RenderStageNow()` 完成后标记 `_modelRendered`；用例还会读取 RT 像素，要求至少 64 个非透明像素。本轮四格实际分别为 `20208/31165/24249/7126`，不再用“Renderer 存在”替代画面存在。
- `config_goods` 的 key 3 是详情/获取提示，保留在详情滚动组；key 35 是来源，放入外部 `sourceGp`。两组按 TMP preferred height 动态排布，并断言不重叠、颜色/对齐正确且品质背景包围全部内容。

## 3. 工作流/Skill 更正

`audit-game-ui-route` 台账先以 schema 3 增加四个结构闸，本轮最终升为 schema 4，再增加实际出帧闸：

- `target_identity` → `identity_evidence[]`：具体 View、主底图、根尺寸、遮罩身份。
- `layout_structure` → `layout_evidence[]`：ScrollRect/Viewport/Mask/Content/Layout/Fitter 结构。
- `scroll_interaction` → `interaction_evidence[]`：真实射线拖动、Content 位移、末项可达。
- `page_space_geometry` → `geometry_evidence[]`：页面根左上角矩形，不只记局部锚点。
- `render_completion` → `render_evidence[]`：相机实际渲染完成标记与 RT 非透明像素探针；仅绑定 RT 不算通过。

`fix-view` 同步增加五类诊断：跨父容器偏移、只有横排没有滚动、打开了错误通用弹窗/动态底图未赋值、RT 提前 ready、动态语义组重叠。最终截图写入新的不可变目录，禁止覆盖已被图片查看器映射的 PNG 后误读旧证据。用户新截图能直接把历史 `done` 回卷为 `defect`。

## 4. 验证结果

- 第一次自动回归在新结构/身份/拖动/页面坐标闸下业务全绿：四个条件格耗时 `184/12/13/11ms`，设置首开 `2034ms`、热开 `103ms`，点击后 `addedResources=none`。
- 但人工查看该轮六张截图发现品质底图透明，主动判定失败并补充 Sprite 实绘闸；这次“机器绿、截图红”的案例正是本轮新增工作流的依据。
- 最终常驻 Editor 回归 `SettingFashionCurrentCase` 返回 `code=0/pass=True`。时装列表结构、裁剪和真实拖动均通过；套装竖牌页面矩形通过；四个条件格逐叶通过正确弹窗身份、动态品质底图、实际模型像素、特效、文案分组、背景包围盒、遮罩外关闭、单次低于 5 秒和点击后零运行时导入。
- 四格详情/来源矩形分别为：前三格详情高 `183/183/239`、第4格详情高 `239`；来源组位于详情之后且无重叠，最长来源自动换行至 `62px`。最终证据保存在 `output/settings_fashion_round4_delivery/`。
- Fashion 资源闭包最终为 720 项，第二次预检 `imported=0/configured=0/added=0/missing=0`；最终 C# 模块与 Editor 构建均为 0 error。未进行 WebGL 构建或部署后复验，因此只标记 Editor 真实 Prefab 路线完成。

## 5. 边界

- 本轮只对 2D 做像素/页面矩形一致；3D 按用户确认的口径验模型存在、位置比例大致正常、无镜像/翻转/明显角度错误并保持模型特效，不要求跨引擎逐像素重合。
- 继续直接修改当前 `FashionModule.prefab`；没有重转 Fashion 模块，也没有把页面视觉搬回运行时代码。
- 未打 WebGL，不能把 Editor 真实 Prefab 验收描述为部署后通过。
