# MainUI 挂机“提升”按钮与扫光对标（2026-08-04）

## 目标与基线

本轮目标是挂机经验条右侧绿色“提升”按钮本身，以及按钮内部循环从左向右掠过的亮光；不是下方通知图标，也不是通知图标的摇摆动画。用户给出的近景、老端全图和修复前 Unity 全图已固化到 `output/ui_route_audit/2026-08-04_mainui_onhook_boost_sweep/`。

老端权威行为位于 `yu_client/h5/src/mainUI/MainUISecondaryView.ts`：

- 未点满且没有 `buff_type == 1` 的经验 Buff 时，`AddOutlineEffect(1)` 在 `add` 宿主上以 `scale=35` 循环播放 `UI_tisheng`；
- 已有经验 Buff 时显示静态 `_img_add`，并释放 `UI_tisheng`；
- 加成点满时隐藏 `add_btn`，同时释放特效。

`UI_tisheng` 不是单纯的透明扫光叠层。原始 `UI_tisheng.lh` 同时包含绿色按钮视觉、3 秒循环的缩放呼吸和 1.333 秒循环的材质 `_BaseMap_ST.z` 扫光，因此只保留静态按钮图或只挂一张高亮图都不等价。

## 根因

当前实际进入 `MainUIModule` 的挂机区域是 `Assets/Prefabs/UI/MainUI/Regions/HudOnHook.prefab`。其 `ExpBoostEffectAnchor` 为空，没有 `UI_tisheng` 的 `UIEffectSlot`，所以 `MainUIOnHookView` 无从加载扫光。

已退出运行链的 `HudSecondary.prefab` 虽残留一个缩放为 1、`autoPlay=false` 的旧占位槽，但它不再由 `MainUIModuleCreator.Parts` 或主界面首屏流实例化，也没有业务消费。这是主界面拆分后动态特效元数据留在退役 Prefab、活动 Prefab 漏接的迁移缺口。

## 修复

- 在当前可编辑 `HudOnHook.prefab/ExpBoostEffectAnchor` 直接保存 `mainui_onhook_boost_hint` 槽，Addressable key 为 `effect/objs/ui_effect/ui_tisheng/ui_tisheng`，`scale=(35,35,35)`、`autoPlay=false`；位置、尺寸和特效参数继续以 Prefab 为唯一视觉事实源。
- `MainUIOnHookView` 按老端条件互斥显示静态 `_img_add` 或完整 `UI_tisheng`，并用版本号收编异步加载。状态切换、View 隐藏和过期加载都会释放旧 `Handle`，避免重复实例、离屏常驻或旧结果回挂。
- `UI_tisheng` 的扫光动画驱动 `_BaseMap_ST`，而公共 `LayaParticleUnlit` 原先只采样 `_MainTex_ST`，造成“按钮能显示、扫光不移动”。Shader 新增材质级 `_UseBaseMapST` 兼容开关，仅给本扫光材质启用；已验收的旧 `_MainTex_ST` 流光保持原路径。
- `UIEffectStage` 只在 PlayMode 调用 `DontDestroyOnLoad`。Editor/CLI 非 PlayMode 仍创建同一公共通道，但不再因非法持久化调用抛异常，离屏 RT 验收可以真实执行。
- `HudOnHook` 已由人工 Prefab 接管，因此从重构 UI 自动重建注册表退出；总装缺失该资产时要求从 Git 恢复，不再用 Creator 重建覆盖已验收槽位。
- 沿用现有 `UIEffectStage` 和已分组的 `UI_tisheng` 资源，没有新增特效资源、Addressables 分组、协议或网络请求。

## 回归门禁

新增 `CliVerify.MainUIOnHookBoost` 和菜单“神霄/验证/MainUI 挂机提升扫光”，验证：

1. 真实 `HudOnHook.prefab` 中槽位、宿主、canonical key、35 倍缩放和手动消费语义；
2. “未点满且无经验 Buff”显示、“已有 Buff”切到静态图、“点满”全部隐藏的状态真值表；
3. Addressable 条目和 `UI_tisheng` 两段循环动画存在，扫光曲线实际驱动 `_BaseMap_ST.z`；
4. 扫光材质显式启用 `_UseBaseMapST`，通过真实 `UIEffectStage` 加载并渲染，分别采样起始帧与中间帧的 RenderTexture 非透明像素和变化像素，同时保存 RT 与完整挂机区域截图；
5. 同一槽不会重复加载，隐藏后释放，重新打开再释放，诊断中不残留活动通道。
