## 1. 目录结构（顶层按部件类型，子夹按 id）

```
ArtsProject/Assets/
  Role/role_{id}/        角色本体(含身体+脸),id=角色 res(1111剑士/1213武姬/1300枪使/1400弓手…)
  Head/head_{id}/        头饰(发型/帽),id=头饰 res
  Weapon/weapon_{id}/    武器,id=武器自身 res(注意:武姬武器是 1200,不是 1213)
  Wing/wing_{id}/        翅膀(以后交付时)
  Back/back_{id}/        背饰(以后交付时)
```

- **子夹名就是检索键**，`{类型}_{id}` 全小写，id 必须是老端资源表里的那个数字。
- 每个子夹内固定四个目录 + 根级 prefab：`Models/`（FBX）、`Materials/`（注意拼写）、`Tex/`、`Timeline/`。
- **不要**把展示场景（SampleScene.unity）、无关测试文件放进交付夹。

## 2. 文件命名

| 类型 | 规则 | 例 |
|---|---|---|
| 动作 prefab（交付物主体，一动作一个） | `{前缀}@{动作名}.prefab`，动作名**全小写、对齐动作名清单** | `1213@idle.prefab`、`head@idle.prefab` |
| FBX | `{id}_{动作名}.fbx`，扩展名统一小写 | `1213_idle.fbx` |
| Timeline | `{动作名}.playable`（小写） | `idle.playable` |
| 贴图/材质 | 语义命名即可 | `Body.mat`、`服饰_橙色.png` |

- prefab 名 `@` 前面的前缀随意（导入时程序会统一改名为 `{id}@{动作}`），**`@` 后面的动作名是键位，拼错=废**。
- **动作名清单**（老端动作系统的既有名字，禁止自创拼法）：
  `idle` `run` `walk` `attack` `attack2` `attack3` `attack4` `skill1`~`skill4` `death` `collect` `jump` `create2` `create3`
  ——常见错误：~~idel~~、~~creator2~~。

## 3. 骨架硬性要求（挂点，最重要）

角色本体（Role）必须有以下**精确小写命名**的挂点，程序按名字精确匹配挂接：

| 节点名 | 挂什么 | 建议父级 |
|---|---|---|
| `head_mount` | 所有头部附件（动态 Head 与静态附件） | 实际头骨（`Bip001 Head` 或变形骨 `head`）下，带绑定姿态逆矩阵补偿 |
| `rhand` | 武器（全职业右手单持） | 右手骨（Bip001 R Hand）下 |
| `root` | 技能/受击特效 | 骨架根、脚底原点处 |
| `wing` | 翅膀+背饰（交付翅膀/背饰时必须有） | 脊柱（Bip001 Spine1）附近 |

- **`head` 可能是实际变形骨，不是挂点。** 不得因为骨骼名刚好是小写 `head` 就把整个头饰 prefab 直接挂上去。
- 所有 Head prefab 都挂到 Role 的 `head_mount`，完整继承身体头骨位移和旋转。带独立 Timeline/Animator 的动态 Head
  继续播放自身发丝/飘带子骨动画；两套 Timeline 可以独立播放，不能再用世界坐标逐帧追位置。
- `head_mount` 在绑定姿态下相对角色 prefab 根必须是单位矩阵（位置 0、旋转 0、缩放 1）。因为它的父级是头骨，
  所以它相对父级的 Local Position/Rotation 通常**不是零**，禁止手工 Reset Transform。
- 美术不必在 Max 手算逆矩阵：可以不导出 `head_mount`，在 Art 项目运行菜单
  **「交付/补挂点(Role 全部)」**自动生成；若骨架或绑定姿态更新，运行
  **「交付/重建 head_mount(Role 全部)」**重新烘焙。
- **大小写敏感**：`Root` ≠ `root`。
- Head 资源内必须有一个根直属、单位变换、精确小写的 `head_attach`。这是附件唯一定位点；`Bone_head` 只负责蒙皮/动画，
  不再兼任程序挂点。旧资源缺 `head_attach` 时程序仅临时回退 `Bone_head`，不得作为新交付方式。
- `rhand` 必须位于角色实际右手骨下，负责跟随手部动作并统一握持方向，不能直接清零到腕骨原点。1213 右手网格
  实测握持中心为 `position(-0.14,0.03,0.02) / rotation(0,0,0) / scale1`；同一骨架的所有动作共用这一份校准。
  新骨架若右手骨轴不同，应在该角色模板的 `rhand` 一次性归一，不能要求每把武器分别反向修正。
- 每个 Art `role_{id}` 文件夹必须带 `role_mount_profile.json`。同 1213 骨架复制
  `Assets/Role/_Template/role_mount_profile.json`；不同骨架由美术只校准该 profile。缺 profile 时 Art 检查直接失败，
  工具不再为未知骨架自动生成腕骨原点 `rhand`。
- Weapon 资源内必须有一个根直属、scale1、精确小写的 `weapon_attach`，作为唯一握点。它的局部 position/rotation
  描述该武器真实握柄中心和轴向，**不要求为零**。旧资源缺该节点时程序仅按 prefab 根临时兼容；新交付禁止依赖此回退。

## 4. 动作与部件配套

- 头饰/翅膀等**跟随动作的部件**：每个动作与本体同名交付（本体有 `idle`，头饰也要 `head@idle`），
  动作不全时程序用已有的顶（当前 1213 头饰只有 idle/create3，缺 attack/run/walk/death——后续补）。
- Head prefab 从 `Assets/Head/_Template/HeadAttachmentTemplate.prefab` 复制，固定结构如下：

  ```text
  head@动作          position 0 / rotation 0 / scale 1
  ├─ head_attach    position 0 / rotation 0 / scale 1
  └─ head_content   新资源 position 0 / rotation 0 / scale 1
  ```

  FBX 模型、`Bone_head`、Animator 和发丝/装饰骨都放进 `head_content`。不得动画 prefab 根、`head_attach` 或
  `head_content`；同一头饰所有动作的 `head_content` 变换必须一致。
- 新头饰在 3D 制作阶段对齐 1213 标准头模，导出前 Reset XForm，并保持与 Role 一致的单位、坐标轴和骨架根约定。
  导入后程序装配值必须是位置 `(0,0,0)`、旋转 `(0,0,0)`、缩放 `1`，不能靠逐件运行时补丁过验收。
- Role 与 Head 的同名动作不强制时长相同，但起始定位和骨架语义必须一致；交付前至少抽查
  0%/25%/50%/75% 四帧以及正面、背面、左右侧四个方向。
- Art 项目菜单 **「交付/头饰/检查全部 Head prefab」**必须 0 失败。1213 旧 FBX 的历史校准已经一次性烘焙在
  `head_content`，其数值只用于旧资源迁移，不是新头饰模板值。
- 武器如果无自身动画，交付一个 `{id}@idle.prefab` 静态件即可，角色所有动作复用。固定结构如下：

  ```text
  {id}@idle          position 0 / rotation 0 / scale 1
  ├─ weapon_attach  真实握柄中心/轴向（允许局部 position/rotation，scale 1）
  └─ weapon_content 新资源 position 0 / rotation 0 / scale 1
  ```

  武器 FBX、材质和特效放进 `weapon_content`。在 3D 制作阶段把 `weapon_attach` 放到握柄中心，并按 1213 标准右手
  握持轴对齐；导出前 Reset XForm。程序的额外配置补偿必须是位置 `(0,0,0)`、旋转 `(0,0,0)`、缩放 `1`。
- Art 项目菜单 **「交付/武器/检查全部 Weapon prefab」**必须 0 失败。检查时至少覆盖正面、背面、左右侧，
  以及 `idle/create3/run/attack` 多时刻；武器不得脱手、穿掌、反握或在动作切换时跳位。
- 最终交付前统一运行 Art 菜单 **「交付/检查全部模板与基准」**，必须得到 Role/Head/Weapon 全部通过；
  主工程资产管理导入后还会做第二道结构硬检查，失败资源不会自动写入运行时替换配置。
- 每个动作 prefab 自包含：模型 + Timeline 自播 + 该动作用到的特效，落点约定同创角时代
  （**同一角色所有动作的停放点一致**，出场类动作末帧 = 待机首帧姿势）。

## 5. 程序侧会自动做的事（美术不用管）

导入时自动：整夹保 GUID 拷贝、FBX 二次导入、PandaShader alpha 补丁、根 prefab 统一改名
`{id}@{动作}`、落点采样（角色本体）、挂点体检（缺了会在工具里黄条警告并记台账）、Addressables 登记。
