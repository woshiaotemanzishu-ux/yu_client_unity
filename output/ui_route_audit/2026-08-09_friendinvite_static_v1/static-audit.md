# FriendInvite 静态路线审计（2026-08-09）

## 结论

- 现有 `FriendInviteModule.prefab` 已包含主窗、四页签内容、福利/商店/分享窗和页面专属模板，但此前 Unity 只有 34000/01/05/06/08/12 读侧 Controller/Model，没有运行时主窗类型和 `340` 路由打开器。
- 本轮仅增量接入 `FriendInviteBootstrap → FriendInviteFlow → FriendInviteMainView`：主界面 `340` 可按现有 Prefab 打开/关闭，只展示已加载的只读 34001 摘要；主窗显式不发送分享、领取或兑换协议。
- `34002/03/04/07/09`、`11301/02` 全部保持事务 `blocked`；`34010/11` 继续 KILL/absent，未增加常量、注册、sender、模型或页面。
- 未启动 Unity、浏览器或前台程序，未登录账号、未调用 SDK、未发任何协议；所有玩家可见、射线点击、滚动、弹窗身份、资源 ready、声音、WebGL 与 cold/warm 均为 `needs-runtime-verify`。

## 静态对账

- 老端主窗固定控件：说明、关闭、宝箱预览、条件页签（求助/帮助/升级/助力）、底部共享按钮、红点、倒计时。
- 条件分支：`IsShowAll()` 为假时只显示求助；微信链/微信或 QQ 游戏显示四页签；34012(type=3) 决定先开福利窗还是主窗。
- 列表叶：累计奖励纵向列表；帮助与升级各 8 个好友槽；商店两页签和纵向商品；福利横向奖励；所有奖励格均需核对真实物品详情弹窗身份。
- 协议边界：读侧固定启动顺序 `34001→34012(3)→34005→34006→34008(60)`；等级复走条件保持不变。

## 验证边界

- 静态检查只证明路由/Prefab 脚本身份和禁发边界存在，不证明 Prefab 玩家可见、布局正确或任何业务叶完成。
- 由于本轮明确禁止 Unity/浏览器/写事务，台账没有任何 `done` 叶；父页必然不能收口。
