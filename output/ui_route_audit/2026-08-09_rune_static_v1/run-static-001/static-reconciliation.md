# Rune / 符文静态三方调和（2026-08-09）

## 文件岛与结论

Rune 目标文件在开始时干净。Unity 已有 `Assets/Prefabs/UI/Rune/RuneModule.prefab`，并保存主面板、转化、属性、技能、觉醒、分解、拆解与符文背包等页面节点；业务 View 位于 `Assets/Scripts/Module/Core/Rune/`。Generated Bind 只读核对，未修改。

老端 Rune 不是单页：HUD 秘宝入口先进入 `SecretTreasureMainView`，Rune 主页面再分出符文槽盘、背包镶嵌/替换、升级、转化、属性、技能、觉醒、合成、分解和拆解。Unity Prefab 虽存在，但除双页签与关闭/子窗打开等少量壳行为外，大部分 View 明确把列表、状态、红点与事务降级为空态或日志。

本轮只实施两项静态确定且不需要共享资源的增量修复：

- `RuneMainUIView.OnShow` 每次打开请求 16700，与老端 `RuneMainUIView.InitEvents` 的打开刷新一致。
- `RuneFlow.Close` 隐藏 RuneModule 内全部已显示 `BaseView`，防止 HUD 再点关闭时子窗残留。

## 页面与控件

- 主面板：10 个符文槽、锁定/空槽/已装备状态、当前符文卡、属性与战力、升级成本、技能/觉醒状态。
- 主按钮：转化、查看属性、符文技能、觉醒、合成、分解、镶嵌、替换、升级、前往获取，以及秘宝/副本两个入口。
- 符文背包：列表、空态、镶嵌/替换模式、条目选择与 16701 写事务、获取入口、关闭。
- 转化：兑换列表、碎片成本、16703 兑换、劫魄宝库入口、关闭。
- 属性：属性列表、空态、点击背景关闭。
- 技能：9 个技能位、选择、锁定/激活状态、16710 激活/升级、关闭。
- 觉醒：可觉醒符文列表、属性列表、吞噬材料背包、单选/全选、说明、16707 觉醒、成功即时刷新与特效、关闭。
- 分解容器：分解/拆解双页签和关闭。
- 分解页：符文列表、逐项选择、蓝/紫/橙/红品质筛选、16706 收益预览、获取入口、共享 Goods 分解事务、成功即时刷新/特效。
- 拆解页：符文列表、逐项选择、16709 预览、奖励列表、空态、16708 拆解、成功即时刷新/特效。

## 协议与 Unity 覆盖

- 老端注册 16700..16711；其中 16700 全量、16701 镶嵌、16702 升级、16703 兑换、16704 副本层数、16705 合成预览、16706 分解预览、16707 觉醒、16708 拆解、16709 拆解预览、16710 技能升级、16711 卸下/相关刷新。
- Unity Controller 当前注册 16700/16701/16702/16704/16705/16706/16709，并可请求 15010 `pos=11` 符文背包；16703/16707/16708/16710/16711 与多数 View 消费链未落地。
- `RuneBagView`/条目已有 Prefab 与 Generated Bind，但 Rune 模块没有对应业务 View 类；主面板的镶嵌/替换按钮当前只记日志。
- 转化、技能、觉醒、分解、拆解 View 的主要按钮当前只记日志，列表模板保持隐藏。

## 组件依赖

- Rune 自有：`RuneIcon`、`RuneSpIcon`、`RuneConvertItem`、`RunePropertyItem` 及各分解/拆解/觉醒/技能条目模板。
- 共享：`BaseAwardItem`、`EquipmentItem`、`FightingShowSmallItem`、说明弹窗、Composite、RuneTreasure、DungeonEnterView、Goods 分解链。
- 共享依赖均只做静态影响面登记；本轮禁止修改 Common/MainUI/Generated/Configs/Router/Flow 等共享域，未越界补实现。

## 未运行门禁

用户明确禁止 build、Unity、浏览器和账号写事务。因此没有执行真实 Prefab 点击、两 viewport、像素/滚动、动态特效双帧、16701/02/03/07/08/10 写事务、即时刷新、cold/warm、关闭重开及零残留验证。所有这些缺口均保持 `defect`、`needs-runtime-verify` 或 `blocked`，没有用静态检查伪装完成。
